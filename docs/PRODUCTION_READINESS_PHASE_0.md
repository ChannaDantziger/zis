# תוצר שלב 0 — מוכנות לפריסה

[README](../README.md) · [אינדקס](PLAN_INDEX.md) · [תוכנית פריסה](PRODUCTION_DEPLOYMENT_PLAN.md) · [תוכנית מימוש](IMPLEMENTATION_PLAN.md) · [פערים פתוחים](OPEN_ISSUES.md).

**נבדק:** 17.11.2026. **היקף:** קריאת תיעוד, קובצי `package.json`, lockfiles ובדיקת קיום קובצי Docker/CI. לא הורצו בדיקות/build, לא נבדקו שירותים חיים, ולא נקראו קובצי סביבה או בוצעו פעולות DB. לכן זהו סיכום תיעוד/קבצים ולא אישור מוכנות תפעולי.

## מסקנה

- **השקת Production ללקוחות: חסומה.** מסלול תשלום/חשבונית, אימות DB/Storage ותפעול מלא, בדיקות קבלה וגיבוי/שחזור עדיין אינם מוכחים כסגורים. תוכנית המימוש משאירה את P6, P7, P8 ו־P9 ללא תנאי סיום מאומתים.
- **Staging: ניתן להתחיל תכנון והקמה לאחר החלטות חשבון.** אין הכרח להשלים סליקה אמיתית כדי להקים Staging; יש להשתמש בנתוני בדיקה וב־Sandbox, ולא לחברו בטעות לנתוני Production. לא נמצאה ראיה ש־Staging כבר קיים.
- **אריזת Docker/CI: טרם הוכנה.** קיימים scripts ו־lockfiles לכל שלושת היישומים, אך לא נמצאו Dockerfile, Compose, `.dockerignore` או Workflow של CI בנתיבים שנבדקו. Git נמצא בענף `codex/admin-simplification` עם remote אחד מוגדר; לא נבדקו יעד, הרשאות או סנכרון ה־remote.

## מה אפשר לקדם עכשיו

1. **בעלת האתר:** לבחור Hosting/תקציב, לוודא חשבונות Git/Registry ולקבוע דומיינים וסביבות לפי U09–U10. אין צורך לשתף פרטי כניסה.
2. **פיתוח:** לאחר החלטת יעד, להכין Docker/CI ו־Runbook ל־Staging; קודם לאמת build ו־health, בלי לקשור ל־Production DB.
3. **בעלת האתר ובעלת ה־DB:** לבדוק בקריאה בלבד schema/ledger, במיוחד 011 שנעצרה ואת 010/016/017/018/019 שמצבם מתועד בחלקו כדיווח בלבד. כל שינוי schema נפרד מהפריסה ומבוצע ידנית ב־workflow המאושר.
4. **פיתוח ובעלת האתר:** להשלים חסמי P5–P7 ב־Staging, ואז לבצע שערי P8/P9. אין לפתוח את החנות ללקוחות לפני תנאי הסיום של תוכנית המימוש.

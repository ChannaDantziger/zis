## הקשר ביצוע קודם — 26.10.2026

בעלת האתר עדכנה את [changes.md](../changes/changes.md) והורתה להתחיל בביצוע. בשלב הראשון עובדים במקביל על חנות, ניהול ו־Backend/DB בקבצים נפרדים; אחר כך משלבים ובודקים את החוזים והזרימות. חיבור ספק אשראי, Webhook וחשבוניות נדחה ואינו חלק מהסבב הנוכחי.

ב־Checkout יוצג שלב הדמיה למילוי פרטי אשראי והמשך, ללא שליחת נתוני כרטיס לשרת או שמירתם. כפתור „שלם ללא אשראי — ניסוי” יופעל גם ב־Production רק במסלול שמחייב מנהלת מורשית, יוצר הזמנה שמסומנת כניסוי ומעביר אותה למסלול התפעול כאילו אושר תשלום; הוא אינו מתעד חיוב אמיתי. הזמנה רגילה לא תוכל לעבור כך ל־paid.

הבהרות בעלת האתר: סעיף 20 מתייחס לגלריית הבית הכללית; התראות יעברו לניווט בתוך „ניהול החנות”; מחיר בסיס יופיע בכל אזור משלוח וכללי מחיר לפי כמות יהיו במתקדמות; שדה עריכת תיאור תמונה להנגשה יוסתר בניהול בלבד; בתמונות מוצר יוצג „הוסף תמונה נוספת”. נוספה דרישה לוולידציית טלפון ודוא״ל. אין להפעיל מיגרציות אוטומטית; חיבור DB חי ואימות הרשאות נשארים שלב נפרד.

עודכן: 09.10.2026. זהו תור העבודה הקצר; סדר ותנאי הסיום המלאים נמצאים ב־[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md).

## הקשר הסבב הקודם — 09.10.2026

בעלת האתר ביקשה להשלים באמצעות Sub-agents את העבודה שניתן לבצע כעת, וציינה שתהליך ההזמנה נעצר. פיתוח יצירת הזמנה/checkout ותשלום נשאר בהמתנה; ממשיכים בניהול קטלוג, דוחות אריזה ואספקה, בדיקות איכות והרשאות שאינם תלויים בהפעלתו. אין כתיבה במסד החי, העלאות חיות או הפעלת מיגרציות במסגרת הבדיקות. התוצרים יסומנו כממומשים רק לאחר שילוב ובדיקות; הזרימות עם הזמנות ונתוני עסק דורשות אימות נוסף.

הסבב הקודם הסתיים עם קטלוג, דוחות ואיכות. לפי בקשת ההמשך הושלמו גם תיבת התראות אישית והעדפות, ותצוגת מלאי והיסטוריה; סבב זה מתועד להלן. תהליך ההזמנה נשאר בהמתנה.

## השלמת חידוש Sub-agents — 09.10.2026

שולבו [התראות אישיות והעדפות](ADMIN_NOTIFICATIONS.md) ו־[ניהול מלאי](ADMIN_INVENTORY.md) ב־API ובניווט. הקטלוג תוקן למניעת תגובות ישנות לאחר החלפת משתמש, תחרות בעימוד ויצירה כפולה בניסיון חוזר אחרי שמירה שהצליחה ורענון שנכשל. 64 בדיקות API ממוקדות ו־17 בדיקות Admin עברו, וכן API build ו־Admin typecheck. אלו בדיקות מקומיות ללא DB.

לאחר הפעלה מחדש נוספת בידי בעלת האתר ב־09.10, אומתו בדפדפן עם משתמש מחובר קטלוג, מלאי, התראות והעדפות, תוויות אריזה ורשימת אספקה. כולם נטענו ללא שגיאת נתיב, במצב ריק. מסנן התראות טרם נקראו נטען; שתי העדפות Push מוצגות כמופעלות ללא שמירה. בטופס מוצר חדש אין קטגוריות לבחירה; נוספה הודעה ברורה והשמירה נשארת מושבתת. לא בוצעו כתיבות, העלאות או מיגרציות. אין בכך אימות מלא של נתונים, סכמה או זרימות כתיבה. אימות עם נתונים ושמירות מאושרות, מילוי שבועי ואישור חלקי, Push ומסך משלוחן נשארים פתוחים. יצירת הזמנה/checkout ותשלום נשארים בהמתנה; P7 לא הושלם.

## נקודת מצב

- בעלת האתר דיווחה ש־Login ל־Production עובד ושמיגרציות 001–008 הוחלו ידנית עד הסוף.
- אין ledger שמתעד את ההרצות הידניות. אין להריץ את קובצי המיגרציה שוב, ואין להציג את הדיווח כאימות schema עצמאי.
- כרגע עובדים מול Production בלבד. בהמשך נציע הפרדת DEV/PROD כתשתית נפרדת.
- בקוד קיימים מסכי Login, Dashboard, Orders, פרטי הזמנה, Tasks, Production ו־Settings; החיבור המלא וההתנהגות שלהם מול Production עדיין דורשים אימות.

ב־09.10 בעלת האתר דיווחה שהדשבורד ויתר המסכים נטענים לאחר מעבר ל־Session pooler. לאחר מכן נמצאה רשומת הגדרות חסרה; בעלת האתר דיווחה שהריצה 009, וטעינת /settings עם חנות סגורה אומתה בדפדפן. אין בכך אימות מלא של זרימות כתיבה או schema.

ב־09.10 אומתו גם Dashboard ו־Tasks במצב ריק. במסך הייצור נוספו בחירת תאריך, חזרה להיום ורענון (אומתו בדפדפן), וקישור להזמנות לפי וריאציה (ממתין לנתונים לבדיקה). לאחר הפעלה מחדש בידי בעלת האתר, מסך ההזמנות נטען דרך נתיב העימוד ללא השגיאה במצב ריק; עמודים עם נתונים ובדיקות כתיבה נשארים פתוחים.

נוספה [רשימת ייצור להדפסה](ADMIN_PRODUCTION_REPORT.md) עם שמירה כ־PDF דרך הדפדפן. תצוגה ריקה ופתיחת חלון הדפסה אומתו; PDF עם נתונים, Audit להפקה ותוויות אריזה/אספקה נשארים פתוחים.

## תור העבודה

אתר הלקוחות נוסף ב־09.10: בית, קטלוג, מוצר, גלריות ועגלה קיימים ונבדקו מקומית. לאחר התקנת התלויות בידי בעלת האתר, גם Lint והבנייה העצמאית עברו. [תיעוד](STOREFRONT_IMPLEMENTATION.md). השלמות החנות: תוכן מאושר, נגישות ואימות מוצר/תמונה מול API חי; יצירת הזמנה ותשלום נשארים בהמתנה לפי ההוראה הנוכחית. הניהול ממשיך בשיחה נפרדת לפי בקשת בעלת האתר.

הוראת בעלת האתר מ־08.10: ממשיכים בבנייה ובבדיקות מקומיות; אימות הגישה ל־DB ול־Production יבוצע בסוף. אין להמתין לכתובת חיה כדי להמשיך בקוד. ההשלמות והראיות ב־[דוח האימות](ADMIN_VERIFICATION.md); אין בכך השלמת P7.

1. לסגור פערי Admin במסכים וב־API מול [אפיון הניהול הנייד](planning/ADMIN_MOBILE_SPEC.md) ו־P7 בתוכנית הראשית; לעדכן התקדמות וראיות. תאריך, סינון עיר, מיון, בחירה מרוכזת, פרטי הזמנה ומשימות ידניות קיימים בקוד ונבדקו מקומית ברמת טיפוסים/API. מסנן וריאציה ועימוד הזמנות נוספו בקוד; טעינת הנתיב החדש אומתה לאחר הפעלה מחדש של ה־API; עימוד עם נתונים טרם נבדק. ראו [עימוד הזמנות](ADMIN_ORDERS.md). קטלוג/תמונות, התראות אישיות ותצוגת מלאי שולבו ונבדקו מקומית. השלמות הבאות: אימות חי, מילוי שבועי, תהליכי משימות מערכת, PDF, Push וביטול לפי התלויות. ראו [תיעוד המשימות](ADMIN_TASKS.md).
2. לשמר בדיקות מקומיות ללא DB. בסוף הבנייה לאמת עם בעלת האתר את `/health/ready` וטעינת מסכי Admin לאחר Login. אין לבצע שינוי הגדרות לצורך בדיקה בלי אישור מפורש.
3. להשלים אימות חנות P3/P4 ופרסום מוצר/תמונה אמיתיים. לקבל מבעלת האתר פרטי מוצר אמיתיים, וריאציות, מחירים ותמונות מאושרות לפי U02–U04.
4. לחבר את העגלה הקיימת ל־Quote וליצירת הזמנה לפי P5. להמתין לחשבונות Sandbox/בחירת ספק רק לפני P6: תשלום וחשבוניות.
5. להציע בנפרד תהליך אוטומטי למיגרציות לאחר ייצוב הסכמה הקיימת. אין לנסות ליצור בדיעבד ledger מטעה להרצות הידניות.

## מה דורש את בעלת האתר

- תוצאות/צילום מסך אם אחד ממסכי Admin או `/health/ready` נכשל. אין לשלוח סודות או כתובות DB.
- נתוני קטלוג ותמונות מורשות כשמתחילים את מסלול החנות.
- החלטות או חשבונות ספק רק כשהשלב הרלוונטי מגיע: סליקה/חשבוניות ב־P6; אירוח, דומיין והתראות ב־P8.

# Checkout בחנות — P5

[אינדקס](PLAN_INDEX.md) · [חוזי API](API_CONTRACTS.md) · [מימוש החנות](STOREFRONT_IMPLEMENTATION.md).

מימוש מקומי מ־09.10.2026. אין כאן אישור להפעלת הזמנות ב־Production.

## מה מומש

- מינימום ההזמנה נבדק מול סכום המוצרים בלבד; דמי המשלוח אינם נספרים. Quote ויצירת הזמנה מפעילים את אותה בדיקת שרת.

- `/checkout` מציג פרטי לקוחה, כתובת, הקדשה, הערות ותאריך אספקה.
- אזור ושיטת משלוח נשלפים מהשרת. עיר ושכונה נגזרות מהאזור שנבחר; אין UUID או מחיר משלוח מקומי קבוע.
- חנות סגורה, כשל טעינת אפשרויות, עגלה לא תקינה או אפשרויות משלוח חסרות חוסמים המשך.
- `POST /availability` ולאחריו `POST /quote` בודקים כמות ותאריך ומחזירים סכומים מהשרת.
- אין ניחוש ימי עבודה, cutoff, טווח תאריכים או שריון מלאי בדפדפן.
- שינוי העגלה או המשלוח מבטל את החישוב. תגובה ישנה אינה משחזרת Quote שבוטל.
- `POST /orders` שולח מזהי וריאציה וכמויות ללא מחיר, עם `Idempotency-Key`.
- במקרה של תוצאה לא ידועה, ניסיון חוזר משתמש באותו מפתח ובאותו Snapshot של כל הגוף, גם אם העגלה השתנתה.
- לאחר שמירה מוצגת הזמנה ממתינה; תשלום אינו זמין ולא מוצג אישור חיוב.
- העגלה נשארת ללא שינוי לפני אישור תשלום. אין בקשת ספק סליקה.

## פרטיות והתאוששות

פרטי לקוחה, גוף הניסיון ואסימון האישור נשמרים בזיכרון בלבד. אין כתיבה ל־localStorage/sessionStorage, אין אסימון ב־URL ואין טופס אשראי.

האישור הפרטי נשלף דרך `GET /orders/confirmation` עם `Authorization: Bearer` ו־`cache: no-store`. כשל רענון אינו יוצר הזמנה נוספת.

ניסיון שתוצאתו אינה ידועה נשאר נעול בזיכרון גם במעבר למסך אחר וחזרה אליו באותו יישום. בזמן ניסיון כזה קיים guard ל־beforeunload והודעה שלא לרענן או לפתוח הזמנה נוספת. אין שחזור בטוח לאחר סגירת הדפדפן או רענון שמאושר על ידי המשתמש; זו מגבלה מתועדת עד חיבור התאוששות אורח בשרת.

ביציאה לאחר יצירה, פרטי הטופס והאסימון נמחקים. תקציר ההזמנה הממתינה נשאר בזיכרון כדי למנוע יצירה חוזרת אוטומטית בחזרה ל־Checkout.

## ראיות בדיקה

13 בדיקות Checkout מקומיות עברו ב־09.10: חנות סגורה, כשל טעינה, חוסר מלאי, שינוי עגלה, retry מדויק, כשל אישור, שגיאת עסק, dispose, תגובות Quote ישנות, טעינה בזמן שינוי עגלה, מעבר מסך תוך ניסיון ובדיקת פרטי קשר; 503 של תצורה חסרה מאומתת משחרר את הטופס, בעוד 503 לא מוכר משאיר ניסיון בטוח נעול.

בדיקת טיפוסים ולינט ממוקד עברו. בדיקות משתמש בדפדפן והבנייה המשולבת מדווחות בנפרד במסירת המשימה.

## QA מבודד

`tests/checkout-vite.config.mjs` בונה ל־`dist-checkout-qa` עם API `/api` ו־envDir מבודד. `tests/checkout-preview.mjs` מגיש ב־4185 נתונים סינתטיים בלבד ומדמה הזמנה ממתינה ללא מסד או ספק. אין לפרוס את השרת או את הבנייה הזאת.

ב־10.10 תוקן נרמול נתיב תיקיית הבנייה: לוכסן סופי גרם לבדיקת הגבולות לדחות קבצי אתר תקינים ב־403. בדיקות נתיב עבור דף הבית, נכס ויציאה מהתיקייה עברו. לאחר הפעלה מחדש בידי בעלת האתר ב־11.10, האתר וזרימת ההזמנה המדומה נטענו בדפדפן; פירוט בהמשך. בדיקות HTTP מול API אמיתי נשארות פתוחות.

## מה עדיין חסר

- הפעלת מיגרציית ה־Backend והתצורה הנדרשת לפני בדיקת הזמנה חי.
- ספק סליקה, ניסיון תשלום, Webhook מאומת, אישור חיוב ועדכון מלאי לאחר תשלום.
- אישור PDF, חשבונית וערוץ משלוח אישור.
- התאוששות הזמנה אורחת לאחר רענון בלי שמירת PII או אסימון אישור בדפדפן.

# תכנון גישה מרחוק לעובדי ZIS

[אינדקס](PLAN_INDEX.md) · [קובצי ניסיון](HOSTINGER_DOCKER_PREVIEW.md) · [ארכיטקטורה](HOSTINGER_DEPLOYMENT_ARCHITECTURE.md).

## מצב 22.11.2026

בעלת האתר מבקשת גישה לעובדים ממקומות שונים, ללא סליקה, תוך שימוש במסד הפעיל. צילומי Hostinger מציגים Traefik במצב `network_mode: host`, עם Docker provider, ‏`websecure` ו־resolver בשם `letsencrypt`; תעודות עבור ZIS והגישה בפועל טרם אומתו. [compose.traefik-draft.yml](../deploy/compose.traefik-draft.yml) עודכן בהתאם כ־**טיוטה לסקירה** ואינו מופעל ב־Workflow; Docker ו־VPS לא נבדקו. אין לשנות את Traefik או אפליקציות אחרות.

## מבנה מוצע

שני שמות HTTPS נפרדים: חנות וניהול. Traefik במצב host אמור לפנות לכתובות קונטיינרי Nginx ברשת Docker `zis-private`; Nginx מעביר `/api/` ל־API באותה רשת, וה־API אינו מפרסם פורט לציבור. נדרשת בדיקת ניתוב בין host ל־bridge בפועל. הגישה לניהול עדיין מחייבת אימות והרשאות בשרת; URL ו־CORS אינם מנגנוני הרשאה.

## דרישות לפני שימוש בטיוטה

1. לוודא שני שמות host נפרדים שניתנים לניתוב ל־VPS ולהנפקת תעודה תקפה. לא ניתן להסיק מצילום ש־Hostinger תקצה שמות זמניים ל־Compose מותאם; לבדוק עם Hostinger או להשתמש בדומיין בבעלותך.
2. צילום ה־YAML אימת את `websecure` ואת `letsencrypt`, ואת השימוש ב־host network במקום רשת משותפת. הטיוטה מגדירה רשת `zis-private` ומסמנת אותה ב־Traefik; יש לבדוק שבשרת Traefik אכן ניגש לכתובת ה־bridge ושהשם אינו מתנגש, בלי לפגוע באפליקציות אחרות.
3. להגדיר `CORS_ALLOWED_ORIGINS` בדיוק ל־`https://<store-host>,https://<admin-host>`. ערכי `ZIS_STORE_HOST` ו־`ZIS_ADMIN_HOST` בטיוטה הם שמות host בלבד, ללא `https://` או נתיב. אין להשתמש בסודות בפרמטרי build.
4. לוודא את מסלול בניית התמונות והגעתן ל־VPS: הפעולה של Hostinger שולחת כתובת לקובץ Compose, ולכן אין להניח שמקורות ה־build היחסיים זמינים בשרת. יש לאמת את היכולת או לבנות images ב־CI ולמשוך אותם מ־Registry, עם גרסה מזוהה.
5. לפני חשיפה אמיתית לבדוק גיבוי מסד ותמונות, הרשאות Admin, TLS ורענון תעודה, CORS, מגבלות קצב וכתובת IP מאחורי Proxy, זמינות ו־rollback. לא מריצים מיגרציות. אותו DB משותף פירושו שכל פעולת ניסוי משנה נתונים חיים.
6. לפני קידום ל־`production` נדרשת סקירת קוד המנגנון הזמני לאישור תשלום מדומה והחלטת בעלת האתר אם להסירו או להשאירו עם הגנות; אישור מדומה אינו חיוב כספי ויכול להפחית מלאי. נדרשות גם בדיקות קבלה ומעבר שערי P8/P9 לפני פתיחה מלאה.

הטיוטה מוסיפה רשת ו־labels בלבד. היא אינה מחליפה לבדה את `docker-compose.yml`, אינה מסירה פרסומי loopback קיימים, ואינה נחשבת להגדרה מאובטחת או מאומתת. לא להפעיל Deploy או לשנות `HOSTINGER_DEPLOY_ENABLED` על סמך טיוטה זו.

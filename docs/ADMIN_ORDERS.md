עדכון 26.11.2026: תאריך ההזמנות נשמר בדפדפן בעת רענון ובמעבר בין רשימת ההזמנות לפרטי הזמנה. כשעוזבים את אזור ההזמנות לתחום אחר, תאריך ההזמנות חוזר להיום ומוצגת הודעה זמנית; מסלול היום תמיד מציג את היום הנוכחי. כאשר התאריך שונה מהיום העסקי בישראל מופיעה התראה בולטת במסך ההזמנות בלבד. לאחר 10 דקות ללא פעילות במסך ההזמנות מופיעה תזכורת לתאריך ללא שינוי אוטומטי. בפרטי הזמנה השרת מחזיר כתובות חתומות לתמונות מוצרים, מארזים ורכיבים, והממשק מציג מקום חלופי כאשר תמונה אינה זמינה. הודעת חסימת מעבר להכנה ללא תשלום מוצגת בעברית. בדיקות מקומיות עברו; תמונות Storage, התזכורת והזרימה טרם אומתו בדפדפן מחובר או במסד חי.

עדכון נוסף 26.11: בסיכומי ההזמנות בבית וברשימה מוצגת תמונת המארז עצמו לצד שמו וכמותו, ללא תמונות רכיבים; בפרטי ההזמנה הרכיבים מוצגים בהזחה בתוך מסגרת משותפת, כולל תמונות וכמות למארז וסך הכול. מספר המארזים מופיע מתחת לשם בכתב קטן, ומחיר השורה משמאל למטה לצד הרכיב האחרון. בדיקות מקומיות עברו; תצוגה חיה ו־Storage טרם אומתו.

עדכון ממשק 17.11.2026: באזור `/orders` נוספו כפתורי סינון בודדים לכל שלב, עם צבעי ואייקוני הסטטוס המשותפים למסלול היום, לצד כפתור "הכול" ומספר הזמנות בכל שלב. המספרים נשלפים בספירה לפי תאריך, עיר ומוצר פעילים ומתעדכנים אחרי שינוי סטטוס מרוכז או מפרטי הזמנה באמצעות invalidate של שאילתות הספירה. סרגל הבחירה והפעולה המרוכזת דביק בראש אזור התוכן; תאריך האספקה והמסננים נשארים בגלילה. שינוי הממשק נכתב בקוד, אך טרם אומת בדפדפן עם נתוני הזמנות.

עדכון מקומי 19.11.2026: נוסף מסנן „ממתינה לתשלום” להזמנות `ordered` שתשלומן `pending`. סינון „התקבלה” מציג `ordered` ללא תשלום `pending`, כך שהמונה אינו סופר הזמנה בשני השלבים; „הכול” כולל את שניהם. הספירה והעימוד מחושבים בשרת לפי תאריך אספקה ומסנן עיר. שינוי זה אינו מוסיף סטטוס להזמנה ב־DB. בדיקות מקומיות עברו; DB ודפדפן לא אומתו.

עדכון נוסף 17.11.2026: מעבר מרוכז לסטטוס `in_transit` דורש מספר מארזים לכל הזמנה. ללא הנתון השרת מחזיר `PACKAGE_COUNT_REQUIRED`; הממשק מציג כעת חלון להזנת כמות נפרדת לכל הזמנה ושולח אותה יחד עם בקשת המעבר. `typecheck` עבר; זרימה עם הזמנות אמיתיות עדיין לא אומתה.

החלטת ממשק 17.11.2026: מסך ההזמנות אינו מציג או מסנן וריאציות ואינו שולח `productVariantId`. שדה הסינון והתמיכה ב־API נשמרים לשימוש עתידי בלבד; תקצירי הפריטים מוצגים לפי שם מוצר.

## התנהגות המסך

עדכון 17.11.2026: תאריך ושלב הזמנה נשארים בחזית; עיר ומיון נמצאים באזור סינון נוסף. [פישוט הניהול ואימות](ADMIN_UX_SIMPLIFICATION.md).

- `/orders` מציג את כלל ההזמנות התואמות ואת מספר ההזמנות בעמוד הנוכחי, עם עימוד של 24 פריטים.
- שינוי מסנן או מיון מחזיר לעמוד הראשון ומנקה בחירה; מעבר עמוד מנקה בחירה.
- בחירה מרוכזת חלה על ההזמנות שניתן לקדם בעמוד הנוכחי בלבד. השרת הקיים ממשיך לבדוק תשלום, הרשאה וגרסה בכל מעבר.
- בזמן המתנה לסינון העיר לא ניתן לבחור שורות ישנות. תגובות לשליפות שבוטלו אינן מחליפות את המסנן הנוכחי.
- אם מספר העמודים מצטמצם, המסך עובר לעמוד האחרון הקיים. אין שמירה של בחירה בין עמודים.

## חוזה API

`GET /admin/orders/page` דורש מנהל תפעול פעיל עם `operations_manager` מפורש וכולל `Cache-Control: no-store`.

פרמטרים: `deliveryDate`, `status`, `paymentFilter` אופציונלי (`pending` או `not_pending`), `productVariantId`, `location`, `sortBy`, `sortDirection`, `page`, `pageSize`. בהיעדר `paymentFilter` סינון הסטטוס שומר על התנהגותו המקורית. ברירות המחדל הן עמוד 1 ו־24 פריטים; המקסימום 50. UUID, תאריך, סינון תשלום ועימוד לא תקינים נדחים ב־400 לפני שליפה.

תגובה נוכחית: הממשק משתמש ב־`data` וב־`page` בלבד. API עשוי להחזיר בנוסף אפשרויות סינון וריאציה, שהממשק מתעלם מהן.

```text
{ data: OrderRow[],
  page: { page, pageSize, totalItems, totalPages },
  variants: [{ value: productVariantId, label: productName + variantName }] }
```

הנתיב נרשם לפני `/admin/orders/:orderId`. הנתיב הישן `/admin/orders` נשאר עם תשובת מערך לצורך תאימות. Dashboard משתמש באותה שאילתת רשימה לתצוגה המצומצמת.

ספירה, נתוני עמוד ואפשרויות וריאציה נקראים באותה טרנזקציית `repeatable read read only`. המסננים, limit ו־offset נשלחים כפרמטרי SQL. המיון מוסיף מספר הזמנה ומזהה לשבירת שוויון. כשל גורם ל־rollback ולשחרור client; לא נוצרים נתונים או מיגרציות.

## ראיות ומגבלות

- API build עבר. 13 בדיקות ממוקדות עברו: הרשאות, no-store, עימוד ברירת מחדל, דחיית קלט, ספירה בעמוד ריק, אפשרויות יום, פרמטרים, rollback ושחרור חיבור.
- Admin typecheck עבר. Vite build נחסם ב־EPERM בפתרון נתיב main.tsx גם לאחר ניסיון עם הרשאה נוספת; אין אישור לבניית bundle חדשה.
- בדפדפן הקיים נראו המסנן החדש והמסך המוגן. ה־API הפעיל החזיר `orderId must be a UUID`, בהתאם לניתוב `/page` כפרטי הזמנה בקוד הישן. נדרשת הפעלה מחדש באותה סביבת Production כדי לטעון את הנתיב החדש.
- לאחר שבעלת האתר הפעילה מחדש את ה־API ב־09.10, מסך Orders נטען ללא שגיאת UUID והציג אפס הזמנות ואפס בעמוד הנוכחי. כשל הניתוב הישן נפתר; מצב ריק אומת בדפדפן.
- בדיקת עמודים עם הזמנות אמיתיות ושינוי סטטוס לא בוצעה. אין שינוי הזמנות Production לצורך בדיקה ללא אישור מתאים.
- בעלת האתר דיווחה ב־09.10 שהדשבורד ויתר מסכי הניהול נטענים לאחר המעבר ל־Session pooler. זהו דיווח על המצב לפני שינוי העימוד, ולא אימות עצמאי של כל זרימות הנתונים.

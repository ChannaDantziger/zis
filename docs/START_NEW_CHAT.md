## חידוש ומימוש ההזמנה — 10.10.2026

בעלת האתר ביקשה לחדש את תהליך ההזמנה. הוראת ההשהיה הקודמת של P5 בוטלה; אין בכך הרשאה להזמנה או חיוב אמיתיים. שולבו [יצירת הזמנה ואישור אורח](ORDER_CREATION.md) ו־[Checkout](STOREFRONT_CHECKOUT.md): משלוח מהשרת, זמינות/Quote, שמירת הזמנה ממתינה אטומית, מניעת כפילות ואישור מצומצם. אין הפחתת מלאי לפני תשלום ואין ספק סליקה.

29 בדיקות חנות עברו, כולל 13 בדיקות Checkout, וכן טיפוסים, Lint ובניית QA. 20 בדיקות תחום/Repository ו־5 בדיקות תצורה של API עברו; API build עבר. ארבע בדיקות HTTP נחסמו ב־EACCES גם לאחר אישור מורחב; אימות בדפדפן נחסם ב־timeout לפורט 4185 ובסירוב חיבור ל־5174. לא בוצעו הזמנות או שינויי DB חיים.

לפני הפעלה נדרשים סקירה והחלה מאושרת של מיגרציה 010 (טרם הורצה), תוקף וסוד אישור אורח, שיעור מס מפורש ב־system_defaults.tax_rate, Origin של החנות, קטלוג וכללי משלוח מאושרים. נתונים, DB/RLS ותחרות אמיתית טרם אומתו. P6 — סליקה, Webhook, חשבונית ואישור PDF — נשאר פתוח; אין אישור השקה.

## הגדרת מודל מומלצת

- עבודה שוטפת על הקוד והתוכנית: **GPT-6.1 Sol · Medium**.
- DB, הרשאות, תשלומים, דיבוג מורכב או החלטות ארכיטקטורה: **GPT-6.1 Sol · High**.
- **GPT-6 Astra · High** לסקירה רחבה במיוחד או ניתוח של סתירות וסיכון גבוה; אין צורך לכל תיקון רגיל.
- שינוי קטן ומוגדר או תיעוד: GPT-6 Luna · Low/Medium.

ההמלצה מבוססת על [OpenAI Model Selection](https://developers.openai.com/api/docs/guides/model-selection) ועל [דף GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol): Sol מתאים לעבודה טכנית מורכבת עם איזון זמן/עלות, ו־Medium הוא נקודת פתיחה מאוזנת; High מתאים לדיבוג ותכנון קשים.

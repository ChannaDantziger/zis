# אתר הלקוחות — מימוש וגבולות האימות

[אינדקס](PLAN_INDEX.md) · [תוכנית](IMPLEMENTATION_PLAN.md) · [פערים](OPEN_ISSUES.md) · [הרצה](../apps/storefront/README.md).

תאריך עדכון אחרון: 18.11.2026. זהו מימוש מקומי של חלקי P3/P4/P5; TypeScript עבר לשינוי הניווט, תצוגת הדפדפן טרם אומתה ואינו אישור השקה.

עדכון 18.11.2026: עגלת הלקוחה נשארת עד שקריאת האישור הפרטי מצליחה; רק אז היא מתנקה. אסימון אישור ותקציר ללא פרטי לקוחה נשמרים זמנית ב־`sessionStorage` כדי לשחזר אישור לאחר רענון. לא נשמרים סיסמה או אסימון מנהלת שם. אישור ניסוי דורש `isTest` מתשובת השרת ומחייב כניסת מנהלת, הנשמרת בזיכרון לדקה. לפני ההזמנה, פריטי הסל נשמרים ב־`localStorage` כמזהי מוצר וכמויות בלבד; אין שמירת פרטי לקוחה/אשראי. סליקה אמיתית עדיין לא קיימת.

החלטת בעלת האתר מ־17.11.2026: ממשק הלקוחה עובד עם מוצרים פשוטים בלבד. אין בחירת וריאציה או הוספת וריאציה לעגלה; שורות עגלה שנשמרו בעבר עם מזהה וריאציה אינן נטענות. חוזי API יכולים להשאיר שדה אופציונלי לעתיד.

## יכולות קיימות

עדכון 26.11.2026: מימוש מקומי לענף 2 מוסיף תצוגת מארזים שפורסמו לפני מוצרים וחלונית הרכבה לפי הקטגוריה, מלאי פיזי ומחירי יחידה. כמות המארזים והרכבם משפיעים על המחיר המוצג; הוספה לסל והזמנה אינם ממומשים. API ופרסום דורשים את סכמת 020/021; 021 הוכנה בלבד ולא הורצה בידי הפיתוח. בנייה, lint ו־37 בדיקות חנות עברו; בדיקת DB ופרסום מחובר עדיין פתוחה. [פרטי אימות](ADMIN_BUNDLES.md).

עדכון 26.11 לאחר פרסום מארז: הקטלוג מציג אזורים נפרדים „מארזים” ו„מוצרים” ללא ספירת פריטים, ואייקון מידע ליד מחיר המארז מסביר שהמחיר מותאם לתכולה. בחלונית מחשב הבחירה מופיעה לצד תמונת המארז; בנייד מוגדרת פריסה אנכית. בדפדפן המקומי אומתו האזורים, חלונית מחשב, אייקון המידע ובחירת מארז ממוצר יחיד ללא סגירת החלונית. תצוגת נייד, אימות ledger ישיר ומסלול רכישה עדיין פתוחים.

עדכון מאוחר 26.11: רשימת מוצרי המארז מוצגת בגובה קבוע עם גלילה; עמודת „מארז ממוצר אחד” כוללת תיבות בחירה והסבר, ושאר השורות מתעמעמות בבחירה. מתחת לרשימה המחיר, מספר המארזים ואייקון התאמה אוטומטית נמצאים בשורה אחת. פריסת מחשב נצפתה בדפדפן; תצוגת נייד טרם אומתה.

- `apps/storefront` הוא Build נפרד מהניהול, עם React, TypeScript, Mantine, MobX, Query ו־Router.
- דף בית עם לוגו זיס, צבעים ופינות לפי המקור המאושר, תמונת מוצר מה־API או תצוגת מותג כשאין תמונה; ללא נכסי מוצר דמוניים בחבילה החיה.
- עדכון 18.11: הקטלוג, גלריית האירועים והשאלות והתשובות נמצאים ברצף דף הבית. קישורי הניווט גוללים לעוגנים; `/catalog` מפנה לעוגן הקטלוג, ופרטי מוצר נפתחים כחלונית מעל הבית. עגלה ו־Checkout נשארים מסכים נפרדים.
- קטלוג אחד כחלק מדף הבית: חיפוש, קטגוריה, מיון ועימוד בשרת; מסננים ועמוד נשמרים ב־URL. קיימים מצבי טעינה, ריק ושגיאה עם ניסיון נוסף.
- פרטי מוצר נפתחים בחלונית מעל הבית גם בקישור ישיר; מחיר ליחידה, מספר היחידות הפיזיות ב־Set וכמות Sets מוצגים למוצר פשוט. המחיר מוצג כמחיר ליחידה × גודל Set = מחיר Set, וכמחיר Set × כמות = סך השורה. הוספה נדחית אם החנות אינה מאומתת כפתוחה או הכמות אינה חוקית.
- עדכון 29.10: ב־Cart וב־Checkout מוצג סכום המינימום, הסכום החסר ושאלה מה להוסיף. המינימום הוא סכום מוצרים בלבד ללא דמי משלוח; מעבר נחסם אם הסכום מתחת למינימום או אם ערך המינימום לא נטען.
- עדכון 01.11: שאלות FAQ מודגשות והתשובות נשארות במשקל רגיל. ברכיבי ממשק ובתמונות הרלוונטיות שלוש הפינות חדות ורק הפינה השמאלית התחתונה מעוגלת. השינויים בקוד; לא נבדקו בדפדפן.
- עדכון 17.11: ממשק הלקוחה מציע מוצר פשוט בלבד; אם ה־API מחזיר מוצר מורכב, לא מוצגות לו אפשרויות רכישה.
- אימות שינויי 15.10: TypeScript ו־ESLint עברו מקומית. תצוגת דפדפן של השינוי טרם אומתה.
- גלריית מוצר ואירועים נפרדות, עם הגדלה, חצים, ממוזערות, Escape, מיקוד בחלונית ומצב חלופי לתמונה שלא נטענת. בגלריית אירועים חמש עמודות במחשב ופחות בנייד.
- עגלה פשוטה עם הוספה, איחוד לפי מוצר, שינוי כמות, הסרה ושחזור. שמירה מקומית כוללת רק מזהי מוצר וכמויות; אין מחיר סמכותי או פרטי לקוחה באחסון.
- טעינת פרטי העגלה מקטלוג עדכני; מוצר חסר או כמות מעל המלאי חוסמים המשך ומציגים הודעת חוסר. כשל טעינה אינו מוחק את העגלה.
- עדכון 29.10: ניתן לשנות כמות, להוסיף, להסיר ולהחליף פריטים בהזמנה ממתינה לפני תשלום דרך API מאומת באסימון אישור, עם בדיקת זמינות/מינימום, חישוב סכומים מחדש ו־Idempotency. להוספה בוחרים מוצר בקטלוג, חוזרים מהעגלה לעריכת pending ומייבאים אותו במפורש; קיימת החזרה מפורשת של פריט שהוסר. פריטים קיימים שומרים Snapshot ומחיר יחידה; פריטים חדשים מקבלים Snapshot מהשרת. אי אפשר לשמור הזמנה ריקה, והיא אינה שומרת מלאי או משנה סטטוס.
- עדכון 10.10: `/checkout` חובר לזמינות, Quote ויצירת הזמנה ממתינה עם אישור אורח. אין ספק תשלום או חיוב; [תיעוד P5 ומגבלות ההפעלה](STOREFRONT_CHECKOUT.md).

**אימות השינויים מ־29.10:** לא הורצו בדיקות, TypeScript/Lint או בדיקת דפדפן; אין אימות DB/HTTP/Production. תוצאות האימות שלהלן מתארות ריצות קודמות בלבד ואינן מכסות את עדכון זה.

## API ציבורי לגלריית אירועים

נוסף `GET /event-gallery` במבנה Routes/Controller/Service/Repository. הוא מחזיר `{ data }` עם `imageId`, `url`, `altText`, `caption`, `sortOrder`.

ה־Repository מסנן `is_published=true` ו־`is_deleted=false`, וממיין לפי סדר ומזהה יציב. ה־Service יוצר Signed URL ב־bucket האירועים ואינו מחזיר `storage_path`. השירות מחובר ב־bootstrap כאשר DB ו־Storage מוגדרים. לא נוספו או הורצו מיגרציות בעבודה זו.

## אימות מקומי

| בדיקה | תוצאה | מה הוכח |
|---|---|---|
| TypeScript בחנות | עבר | טיפוסים בחיבור התוצרים |
| Build ב־Vite | עבר | `npm run build` עם ההתקנה העצמאית של החנות והגדרת `preserveSymlinks` |
| עגלה | 12 עברו | שחזור פגום/ישן, גבולות כמות, איחוד, שינוי מחיר/מלאי, מוצר שנעלם, תחרות רענון וכשל אחסון/רשת |
| קטלוג ובחירה | 4 עברו | נרמול URL, איפוס עמוד, וריאציה זמינה/מינימום ובחירת תמונות |
| דפדפן עם API מדומה | עבר ב־1440/390/320 | ללא גלישה אופקית או שגיאות JavaScript; עגלה, חיפוש, גלריה ומצבי קצה |
| Repository גלריית אירועים | 2 עברו | סינון, סדר יציב ושחרור client בהצלחה ובכשל |
| HTTP לגלריה | חסום | `EACCES` ב־localhost; אין תוצאת pass |
| ESLint והתקנה עצמאית | אומתו לאחר התקנת בעלת האתר | `npm run lint` עבר; קובץ נעילה קיים; טיפוסים ו־16 בדיקות עברו עם תלויות החנות |
| DB/Storage ונתוני עסק חיים | לא נבדקו | אין הוכחה לפרסום תמונה או מוצר ב־Production |

מסלול האימות החלופי ב־[verify-existing-dependencies](../apps/storefront/tests/verify-existing-dependencies.mjs) משתמש בהתקנת Admin קיימת, כותב תצורה זמנית ומתעלם מקובצי סביבה. לאחר התקנת בעלת האתר ב־09.10, כל פקודות הבדיקה הרגילות עברו עם תלויות החנות. `preserveSymlinks` הוסף גם להגדרת Vite כדי לפתור כשל `realpath/EPERM` בתוך סביבת הסוכן; ניסיון בנייה מחוץ להגבלה לא אושר ולא בוצע. אין שינוי בתלויות ה־Admin.

אזהרת Build: חבילת JavaScript הראשית גדולה מ־500 kB לפני gzip. יש לשקול פיצול עמודים בטעינה עצלה לפני P8.

## בדיקות דפדפן

[browser-smoke](../apps/storefront/tests/browser-smoke.mjs) מפעיל Chromium במצב headless ומגיש Build ו־API מדומים באמצעות interception. כל הנתונים מסומנים כבדיקה; אין בקשות ל־Production או ליעד חיצוני.

הבדיקה עברה ב־09.10.2026 ברוחבי 1440, 390 ו־320, ללא גלישה אופקית או שגיאות JavaScript. היא מכסה בית, RTL, מוצר, הוספה לעגלה, שינוי כמות ושחזור, הסרה, הגדלה ודפדוף בגלריה, חיפוש עם URL, חנות סגורה, API שנכשל וקטלוג ריק. [תוצאות](../apps/storefront/tests/screenshots/checks.json), [צילום מחשב](../apps/storefront/tests/screenshots/home-1440.png) ו־[צילום נייד](../apps/storefront/tests/screenshots/home-390.png).

```powershell
Set-Location apps/storefront
node tests/browser-smoke.mjs C:/path/to/bundled/node_modules
```

נדרש Playwright מותקן ו־Chrome בנתיב המופיע בסקריפט. אפשר להתאים את הנתיב למכונת הבדיקה. ניסיונות בדפדפן המובנה ובשרת localhost נכשלו בגישת רשת; אין להסיק מהם כשל בחיבור API חי.

## מה נשאר

1. אישור חזותי עם תוכן אמיתי ובדיקת נגישות מלאה; התקנה עצמאית, קובץ נעילה ו־Lint הושלמו.
2. פרסום מוצר/תמונה אמיתיים בניהול ואימות DB, הרשאות Storage ו־Signed URLs אחרי תפוגה.
3. ניהול העלאה/פרסום גלריית אירועים; FAQ ותוכן עסקי מאושר.
4. P5: להפעיל תצורה ומיגרציה 010 בתהליך מאושר ולאמת Checkout/יצירה עם נתוני בדיקה; [Runbook](ORDER_CREATION.md). אימות HTTP ודפדפן מלא נחסם ב־localhost. P6: תשלום וחשבוניות.
5. P7–P9: יתר התפעול, Push/PDF, פריסה, ניטור וגיבוי שנבדק.

הניהול נערך בשיחה אחרת לפי אישור בעלת האתר. השינויים הזמניים של סוכן הניהול בשיחה זו הוסרו תוך שמירת עבודת השיחה האחרת.

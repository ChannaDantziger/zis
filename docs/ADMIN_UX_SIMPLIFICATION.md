# פישוט אזור הניהול

[אינדקס](PLAN_INDEX.md) · [קטלוג](ADMIN_CATALOG.md) · [הגדרות](ADMIN_COMMERCE_SETTINGS.md) · [פערים](OPEN_ISSUES.md).

עודכן: 21.10.2026. השינויים ממומשים בענף `codex/admin-simplification`.
האימות מקומי; אימות חזותי ופעולות מול DB/Storage חיים פתוחים.

## החלטות בעלת האתר

- תחילה שמירת המצב הקיים והעלאתו לגיט, ואחר כך ענף חדש לשיפור הניהול.
- בחירת קטגוריה וניווט בה באמצעות פירורי לחם.
- הפרדה בין עריכה רגילה למתקדמת; וריאציות שייכות למתקדמת.
- סדר העבודה: קטלוג, הגדרות חנות ומשלוח, ואז הפחתת עומס במסכים היומיומיים.

## קטלוג — ממומש בקוד

- מסך הכניסה מציג קטגוריות. בחירת קטגוריה מציגה את מוצריה בלבד.
- פירורי הלחם הם הקטלוג, הקטגוריה והמוצר. אפשר לחזור לקטגוריה ולמסך הקטגוריות, ולהחליף קטגוריה בתפריט שבפירור הקטגוריה.
- מוצר חדש מקבל את הקטגוריה שנבחרה. אין שדה בחירת קטגוריה בטופס הרגיל.
- יצירת קטגוריה דורשת שם בלבד; סדר והסתרה נמצאים בהגדרות מתקדמות. אחרי יצירה עוברים למוצרי הקטגוריה החדשה.
- עריכה רגילה מציגה שם, תיאור, מחיר ליחידת קנייה וכמות במלאי למוצר רגיל. מספר היחידות בכל יחידת קנייה מוצג כמידע.
- במוצר עם וריאציות המחיר והמלאי ברמת המוצר אינם מוצגים כשדות; העריכה שלהם נעשית דרך הווריאציות במתקדמת.
- עריכה מתקדמת כוללת העברה לקטגוריה אחרת, יחידות בסט, סדר הצגה, מצב פרסום ווריאציות. מעבר בין המצבים שומר את טיוטת פרטי המוצר והווריאציה בזיכרון.
- קוד וריאציה קיימת מופיע כטקסט, ולא כשדה מושבת. ביצירת וריאציה עדיין צריך להזין קוד.
- תמונות מוצר זמינות לאחר השמירה הראשונה. בעריכה רגילה מוצגות תמונות המוצר; שיוך לווריאציה וסדר תמונה מופיעים רק במתקדמת.
- מעבר ממתקדמת לרגילה מנקה עריכת תמונה שמשויכת לווריאציה, כדי למנוע שמירת שיוך מוסתר. יש להשלים את שמירת התמונה לפני המעבר.
- כל סיבות אי־ההצגה של מוצר מוצגות בטקסט; אין תלות במעבר עכבר מעל תג.
- שינוי פרטי מוצר דורש שמירה לפני פעולות תמונה או וריאציה, כדי שרענון הפעולה לא ידרוס טיוטה.
- ניווט פנימי בפירורי לחם או חזרה מהמוצר מבקש אישור אם פרטי המוצר השתנו ולא נשמרו. אין חסימת יציאה כללית דרך תפריט האתר או סגירת הדפדפן.

## API של הקטלוג

`GET /admin/products?page=2&categoryId=<uuid>` מסנן בשרת, כולל ספירת המוצרים והעימוד, באותה טרנזקציית קריאה.
`categoryId` אופציונלי ועובר אימות UUID והרשאה לפני שליפה. רשימת הקטגוריות המלאה נשמרת בתשובה כדי לאפשר ניווט.
מחיר מוצר יכול להישאר `null` בעריכת מוצר שמחיריו מוגדרים בווריאציות; יצירת מוצר רגיל עדיין דורשת מחיר תקין.
כללי פרסום, גרסאות ו־Audit ממשיכים להיאכף בשרת. השינוי אינו דורש מיגרציה.

## הגדרות חנות ומשלוח — ממומש בקוד

- שלוש לשוניות: החנות והזמנות, משלוחים ומחירים, ותאריכים חסומים.
- טופס החנות משתמש בשפה פשוטה ובבחירת שעות. אזור הזמן מוצג כמידע במתקדמת; סטטוס הכנה טכני אינו מוצג כשדה.
- מתג קבלת הזמנות משקף את הצירוף `storeOpen && lockMode === 'open'` שבו משתמש השרת. פעולה במתג מעדכנת יחד את הפתיחה ואת הנעילה לפתוח/סגור. סגירות ותאריכים נוספים ממשיכים לחול בנפרד.
- מצב נעילה מתוזמן נשאר במתקדמת; שינוי המתזמן אינו מפעיל מנגנון תזמון חדש.
- משלוחים מוצגים כסיכומי מחירים ואזורים הנפתחים לעריכה. טווחי כמויות ותוספות מחיר נמצאים במתקדמת. שיטות משלוח נמצאות באזור מתקדם נפרד.
- אין ברירת מחדל שקטה לאזור/שיטת משלוח ביצירת מחיר; יש לבחור במפורש.
- סגירה קיימת נפתחת לעריכה ונשמרת רק בלחיצה על שמירה. תחילה וסיום נשלחים יחד לאחר אימות הסדר ביניהם, ולא בכל שינוי שדה.
- טופסי הוספת אזור, מחיר וסגירה מתנקים רק לאחר תשובת הצלחה.

## מסכים יומיומיים — ממומש בקוד

- הזמנות: תאריך ושלב בחזית; עיר, מוצר/וריאציה ומיון תחת סינון נוסף. מסננים פעילים מוצגים גם כשהאזור סגור, עם אפשרות להסרה.
- הזמנה שאין לה מעבר סטטוס זמין אינה מציגה תיבת בחירה מושבתת.
- מלאי: כמות זמינה ועדכון בולטים; תכנון קיבולת, פרטים והיסטוריה נפתחים בנפרד.
- עדכון מלאי מציע הוספה/הפחתה וכמות חיובית. מוצגת הכמות הצפויה אחרי השינוי; הפחתה מעבר למלאי המוצג אינה זמינה. אימות השרת נשאר מחייב.
- דוחות: תאריך והדפסה בחזית; סינון נוסף מקופל. כשמסמנים הזמנות מופיעה פעולת הכנת הנבחרות להדפסה ליד כפתור ההדפסה.

## אימות וגבולות

- בדיקת טיפוסים ובניית Admin ובניית API עברו. Vite עדיין מציג אזהרה על bundle מעל 500 kB.
- 25 בדיקות Admin עברו: 24 בהרצת החבילה המלאה, ועוד בדיקת ניקוי מסננים בהרצה ממוקדת של שש בדיקות מצב ההזמנות. כל 20 בדיקות ה־API הממוקדות עברו, כולל סינון ועימוד קטגוריה, מחיר מוצר ריק עם וריאציות, תמונות, הרשאות, גרסאות ו־Quote.
- שבע בדיקות יצירת HTML מרכיבי React עברו עם נתוני דוגמה: רגיל/מתקדם, מוצר עם וריאציות, קוד קבוע, סגירות, משלוחים ומלאי. זו בדיקה של רכיבים בפועל ללא דפדפן; היא אינה מאמתת נראות או אינטראקציה.
- ל־Admin לא מוגדר סקריפט Lint; אין טענה שבדיקת Lint עברה.
- בניית תצוגת דוגמה מבודדת עברה. כלי הדפדפן לא הצליח להתחבר לשרת המקומי; HTTP נכשל בהרשאת socket גם בניסיון נוסף עם הרשאה מורחבת. אין בכך אימות חזותי.
- לא בוצעו כתיבה למסד חי, העלאת מדיה חיה או מיגרציות.
- מלאי למוצרים רגילים, מילוי שבועי, Push, תשלום ויתר פערי P7 אינם מושלמים במסגרת פישוט התצוגה. ראו O18.
- במסמכי המשלוח תוספות זמן ודחיפות תוארו כמושבתות, אך קוד Quote מחבר אותן למחיר. ההתנהגות לא שונתה; ההכרעה רשומה ב־O25.

## המשך אימות

1. בדפדפן בנייד ובמחשב: קטגוריה, מעבר עמוד, מוצר חדש, חזרה בפירורי לחם, והחלפת עריכה רגילה/מתקדמת.
2. בסביבת בדיקה מורשית: שמירת מוצר רגיל, עריכת מוצר עם וריאציות, תמונה ושמירה מחדש אחרי כשל רענון.
3. הגדרות חנות ומשלוח: פתיחה/סגירה, מחירים, תאריכים חסומים ובדיקת ההשפעה ב־Quote.
4. מלאי ודוחות: הוספה והפחתה, כשל בקשה, הדפסה חלקית ושמירה כ־PDF עם נתונים.

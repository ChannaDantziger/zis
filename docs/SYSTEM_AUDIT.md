# סקירת מערכת, מסמכים ו־HTML

[אינדקס](PLAN_INDEX.md) · [פערים לטיפול](OPEN_ISSUES.md) · [תוכנית](IMPLEMENTATION_PLAN.md).
תאריך: 18.09.2026. זו סקירת המאגר ומקורות HTML שנמצאו, לא אישור מוכנות להשקה.
עדכון נפרד מ־22–23.09: [סקירה חזותית ותצוגת זיס](planning/VISUAL_REVIEW.md), כולל בדיקת דפדפן ולוגו. הממצאים להלן נשמרים כתמונת מצב מתאריך הסקירה המקורי.

## מסקנה

קיימים תכנון רחב, אב־טיפוס חנות ושלד Backend חלקי. ליבת החנות לא נעלמה מכל המסמכים — FRONTEND_BUILD_PLAN כבר תיאר חלק ניכר ממנה — אבל היא לא מומשה במאגר וסדרי ההמשך התמקדו במלאי. תוכנית העבודה המאוחדת מחזירה קטלוג, תמונות, תצוגה, עגלה ותפעול למסלול מחייב עם תנאי סיום.

## היקף ומה לא אומת

- נסרקו כל 22 קובצי ה־MD שהיו במאגר בתחילת הסקירה, כולל docs, scripts, zis-api, zis-db ו־.codex.
- נבדקו קובצי המקור והבדיקות של ה־API, package.json/tsconfig וארבע המיגרציות.
- נקראו ההנחיות החיצוניות דרך הכנה בטוחה; נוסף עותק מקומי ב־[GUIDELINES](GUIDELINES.md).
- נמצאו שני קובצי HTML בתיקיית ליס; נבדקו תבנית ה־HTML וקוד היישום הכלול בנכסים הארוזים. לא נסקר קוד ספקים דחוס כקוד עסקי.
- קובצי סביבה סודיים לא נקראו. קבצים נקראו רק מעותק PreparedPath שהוחזר מסקריפט ההכנה.
- node_modules, dist, תוכן Git בינארי וקבצים שנוצרו אינם מסמכי עבודה ולא נכללים באינדקס.
- לא אומתו DB חי, Storage, חשבונות ספק, סביבת פריסה או אתר חי. לא בוצעה בדיקת דפדפן חזותית.
- Word/PDF ותמונות המקור החיצוניות לא נותחו; נדרש לאשר אם הם מקור דרישות נוסף לפני סגירת האפיון.

מספר השורות של המעטפת אינו מעיד על מודולריות: שורות ארוכות מכילות קוד/נכסים שלמים. אין לראות ב־180 שורות עמידה במהות כלל הפיצול.

### מה יש בקוד האב־טיפוס

- React עם קומפוננטות קיימות בתוך קבצים ארוזים: Header, Hero, CatalogStrip, ProductsGrid, Packages, Gallery, Brands, Stories, Trust, FaqSection, Contact, Footer, MobileTabBar.
- CartProvider/CartDrawer עם Context ו־localStorage; נתונים מתוך LIS_DATA.PRODUCTS/PACKAGES.
- CheckoutModal, DesktopOneScreen, MobileSteps ו־ConfirmationPane.
- נתוני מוצרים, תרגומים ו־FAQ סטטיים, תמונות ארוזות ומקור תמונות Demo.
- Runtime Babel, CSS ותלויות בתוך האריזה; TweaksPanel כעזר עיצוב.

### מה דורש שינוי לפני שימוש כחנות

- placeOrder בונה מספר אקראי ב־Math.random ומעדכן מצב מקומי. אינו שומר הזמנה בשרת.
- טופס שומר שדות מספר כרטיס/תוקף/CVV במצב React ומציג אישור; אין אינטגרציית סליקה אמיתית.
- איסוף עצמי, משלוח חינם מעל סכום קבוע ואקספרס ציבורי סותרים החלטות קיימות.
- מחירי משלוח מחושבים בקוד הלקוח; כתובת/שעות/הבטחות אישור ותוכן Demo אינם נתונים עסקיים מאושרים.
- יש מבנה רכיבים שניתן לשמר רעיונית, אך צריך להעבירו לקובצי מקור, Mantine/MobX וחוזי API.
- שיפור חזותי מפורט ובדיקת נגישות דורשים בדיקת דפדפן מול המקור שנבחר; לא נטען שהמראה נבדק כאן.

המשימות ותנאי הקבלה מוגדרים ב־[דרישות חנות](planning/STOREFRONT_REQUIREMENTS.md) וב־P3/P4. ה־HTML המקורי לא שונה בסקירת התכנון.

## בדיקות שבוצעו

- npm.cmd run typecheck עבר ב־zis-api.
- npm.cmd test עם RUN_DB_INTEGRATION=false נכשל לפני טעינת tests ב־uv_os_get_passwd/ENOMEM בתוך tsx. ניסיון נוסף מחוץ להגבלת ההרצה נכשל באותה שגיאה.
- לא הופעלה בדיקת DB, מיגרציה או פעולה חיצונית. O12 כולל גם ליקויי fixture שנמצאו בקריאת הקוד.
- בדיקת המסמכים ניתנת להרצה באמצעות [check-docs](../scripts/check-docs.ps1): אורכים, קישורים וכיסוי האינדקס.
- תוצאה לאחר הארגון: 39 מסמכים, 306 קישורים בתוך המאגר ו־5 קישורי קבצים חיצוניים תקינים; כל מסמך מופיע באינדקס והארוך ביותר 292 שורות. הבדיקה אינה בודקת HTTP או עוגני כותרות.

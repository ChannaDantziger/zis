עודכן: 09.10.2026. מימוש מקומי על טבלאות קיימות; אין מיגרציה חדשה ואין שליחת Push.

## מסך ההתראות

`/notifications` מציג רק התראות של המנהלת המחוברת, עם סינון הכל/טרם נקראו/נקראו ועימוד. המסך מציג ספירת התראות שלא נקראו, תוכן, סוג, מועד בשעון ישראל וקישור להזמנה כשהיא קיימת. אין סיכום התראות של משתמשים אחרים.

סימון כנקראה שומר `read_at` ומרענן את הרשימה ואת הדשבורד. לחיצה חוזרת אינה משנה את מועד הקריאה ואינה מוסיפה Audit נוסף. הסימון אינו מסמן שהודעת Push נשלחה או נמסרה.

העדפות `pushNewOrderEnabled` ו־`pushActionRequiredEnabled` נשמרות עבור המשתמש המחובר בלבד. אפשר לבטל טיוטת שינויים לפני שמירה. החלפת משתמש או יציאה מאפסות את המסנן, העמוד והטיוטה. המסך מציין במפורש ששליחת Push למכשיר אינה מחוברת; אינו מבקש הרשאת דפדפן ואינו רושם מכשיר.

## API

כל הנתיבים דורשים `operations_manager` פעיל ומחזירים `Cache-Control: no-store`:

| נתיב | התנהגות |
|---|---|
| `GET /admin/notifications` | `filter=all|unread|read`, `page`, `pageSize`; ברירת מחדל 24 ועד 50 לעמוד; מחזיר `data`, `page`, `unreadCount` |
| `PATCH /admin/notifications/:notificationId/read` | גוף ריק או `{}`; UUID תקין; סימון התראה אישית כנקראה |
| `GET /admin/notifications/preferences` | שתי העדפות אישיות; כשאין רשומה מחזיר ברירות מחדל של הסכמה ללא יצירה |
| `PATCH /admin/notifications/preferences` | Patch לא ריק של ערכי boolean עבור שתי ההעדפות בלבד |

מזהה המשתמש מגיע מה־resolver המאומת ולא מפרמטר בקשה. מזהה משתמש או Push token בגוף שמירה נדחים. התראה לא קיימת והתראה של משתמש אחר מחזירות אותה שגיאת 404, ללא חשיפת בעלות וללא כתיבה.

## אחסון ובידוד

- הטבלאות `admin_notifications` ממיגרציה 003 ו־`admin_notification_preferences` ממיגרציה 006 קיימות בסכמה המתועדת. מצב הסכמה החיה לא אומת בסבב זה.
- שאילתות הרשימה, הספירה והעדכונים מסוננות לפי המשתמש באמצעות פרמטרי SQL. אין שליפה של `push_token` או פרטי מכשיר.
- ספירה ועימוד משתמשים ב־snapshot לקריאה בלבד, עם מיון יציב לפי מועד ומזהה.
- סימון קריאה נועל את ההתראה האישית. העדפות נועלות את רשומת המשתמש גם כשאין עדיין העדפות, כדי ששני Patch-ים חלקיים לא ידרסו זה את זה.
- העדפות וסימון ראשון כנקראה נרשמים ב־`admin_audit_log` באותה טרנזקציה. כשל Audit גורם ל־rollback; עדכון זהה של העדפות קיימות אינו יוצר רישום מיותר.

## בדיקות ומגבלות

- 14 בדיקות API מקומיות עברו: הרשאות, זהות אישית, ולידציה, גבולות עימוד, SQL מסונן, סימון חוזר, חסימת התראה זרה, ברירות מחדל ללא כתיבה, עדכונים חלקיים מקבילים ו־rollback כש־Audit נכשל.
- שתי בדיקות UI-state בודקות שינוי מסנן ושמירת טיוטה וכן ניקוי מצב אישי בהחלפת משתמש. בדיקות הטיפוסים של Admin ו־API עברו. כלל בדיקות Admin המקומיות בסבב המשותף עברו: 17 בדיקות, ובהן שתי בדיקות ההתראות.
- בדיקות SQL משתמשות בלקוח מדומה; אינן מוכיחות RLS או התחברות למסד. לא בוצעו כתיבות ב־Production ולא נשמרו העדפות בדפדפן חי.
- נדרש עדיין אימות מסך מול API פעיל, בדיקה עם התראות אמיתיות ואישור בעלת האתר לפני בדיקת כתיבה חיה.
- יצירת התראות אוטומטית לכל תרחישי המערכת, התקני Push, ספק שליחה, הרשאות דפדפן וניטור מסירה נשארים עבודה נפרדת.

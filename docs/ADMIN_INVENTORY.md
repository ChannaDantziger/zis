# ניהול מלאי וקיבולת ייצור

[אינדקס](PLAN_INDEX.md) · [מודל מלאי](INVENTORY_MODEL.md) · [התנהגות מלאי קיימת](INVENTORY_AND_STATUS.md).
עודכן: 17.11.2026. מסך המלאי בדשבורד מציג קישור לניהול מחיר ומלאי של מוצרים פשוטים במסך הקטלוג. נתיבי מלאי וריאציות נשארים ב־API לשימוש עתידי ואינם מוצגים בדשבורד.

## כלל הממשק

עדכון 21.10.2026: הכמות הזמינה ועדכון מלאי בולטים; קיבולת והיסטוריה נפתחות בנפרד. העדכון משתמש בבחירת הוספה/הפחתה ובכמות חיובית, ומציג את הכמות לאחר השמירה. [פישוט הניהול ואימות](ADMIN_UX_SIMPLIFICATION.md).

`/inventory` מפנה לניהול מלאי מוצרים בקטלוג. מלאי מוצר פשוט נשמר ביחידות פיזיות; Sets שלמים למכירה מחושבים לפי `set_size`.

הדשבורד אינו מציג וריאציות, היסטוריית מלאי או קיבולת ברמת וריאציה. ה־API הקיים מחזיר לכל וריאציה:

- **זמין בפועל**: `available_sets`.
- **תוספת ברירת מחדל**: `default_production_quantity_sets`; זו הצעה לשדה שינוי המלאי, לא כמות שכבר אושרה.
- **סף מלאי נמוך**: `low_stock_threshold_sets`; חיווי מופיע כאשר הזמין קטן או שווה לסף, בהתאם לשירות הקיים.
- **קיבולת ייצור**: רשומת `variant_weekly_capacity` לתאריך `week_start_date` המדויק שנבחר, כולל פעילה/לא פעילה. אין הנחת יום ראשון או שני.
- **הקצאות ייצור**: סכום `production_allocations` במצב `allocated` בחלון שבעה ימים מהתאריך הנבחר. הנתון אינו צריכת מלאי או כמות שנוספה לזמין.
- **מילוי מלאי שבועי מתוכנן/מאושר**: מסומן כטרם מומש. אין בסכמה רשומת מילוי שתומכת באישור מלא/חלקי פעם אחת ולכן לא הומצאה כמות מאושרת או פעולת אישור.

בנתיב ה־API, רשומות וריאציה שלא נמחקו מוחזרות גם במצב מוסתר/אזל/ארכיון; מוצרים שנמחקו אינם מוחזרים. ממשק הניהול אינו קורא לנתיבים האלה.

## API עדכון מלאי (אינו מחובר לממשק הניהול הנוכחי)

`POST /admin/inventory/:productVariantId/adjust` מקבל `deltaSets` שלם שאינו אפס וסיבה שאינה ריקה. הוא אינו מקבל יתרה מוחלטת.

- שינוי חיובי מוסיף מלאי זמין בפועל; שלילי מפחית. השירות נועל את הווריאציה ומתעד את תנועת המלאי.
- אין כתיבה מתוך פתיחת מסך או קריאת API.
- המסלול אינו מספק idempotency key לפעולת המלאי; במקרה כשל רשת יש לבדוק היסטוריה לפני ניסיון נוסף.

## ממשקי קריאה

- `GET /admin/inventory/variants?weekStartDate=YYYY-MM-DD&page=1`.
- `GET /admin/inventory/variants/:productVariantId?weekStartDate=YYYY-MM-DD&page=1` מחזיר פרטי וריאציה והיסטוריית תנועות.
- שני המסלולים דורשים משתמש פעיל עם `operations_manager` מפורש ושולחים `Cache-Control: no-store`.
- תאריך קלנדרי, UUID ועימוד נבדקים לפני Repository. תאריך שבוע אינו מקבל מגבלת יום שלא קיימת בהחלטות או בסכמה.
- נתוני וריאציה, קיבולת, הקצאות וספירת העימוד נקראים ב־repeatable-read read-only transaction. היסטוריה ממוינת לפי זמן ומזהה תנועה כדי שעימוד יהיה יציב.
- פרמטרי מזהה, תאריך, limit ו־offset מועברים ל־SQL בנפרד. אין כתיבת נתונים בממשקי הקריאה.

## קוד וגבולות אימות

[Service](../zis-api/src/inventory-admin/inventory-admin.service.ts), [Repository](../zis-api/src/inventory-admin/postgres-inventory-admin.repository.ts), [Controller](../zis-api/src/controllers/admin-inventory-read.controller.ts), [Router](../zis-api/src/routes/admin-inventory-read.routes.ts) הם API נשמר לשימוש עתידי. מסך [`/inventory`](../apps/admin-mobile/src/pages/InventoryPage.tsx) מפנה לניהול מלאי המוצרים הפשוטים בקטלוג.

בדיקות מקומיות מכסות הרשאות שני המסלולים, no-store, תאריך/UUID/offset לא תקינים, וריאציה חסרה, חלון קיבולת, הפרדה מהזמין, עימוד היסטוריה ו־rollback/release. תוצאות הבדיקות האחרונות מתועדות ב־[התקדמות](IMPLEMENTATION_PROGRESS.md).

## גבולות שנשארו

מילוי שבועי, אישור חלקי ומניעת אישור כפול דורשים רשומת מילוי ומיגרציה חדשה בהמשך. עריכת הקיבולת הקודמת, חלוקת מלאי להזמנות והשלמת deferred אינם מופעלים במסך. לא בוצעה כתיבת מלאי או הפעלת מיגרציה במסד החי במסגרת פיתוח זה; אימות UI ופעולת עדכון עם נתוני בדיקה מאושרים עדיין נדרשים.

# ניהול קטלוג ותמונות

[אינדקס](PLAN_INDEX.md) · [אימות Admin](ADMIN_VERIFICATION.md) · [תוכנית המשך](NEXT_PHASE_PLAN.md) · [פערים](OPEN_ISSUES.md).
עודכן: 18.10.2026. קוד הקטלוג הפשוט, תמונות נפרדות ומסך גלריה כללית ממומשים מקומית. ניסיון להחיל את מיגרציה 011 נכשל עקב הפניה ל־`sku_snapshot` ששמו שונה במיגרציה 003; המקור תוקן ל־`product_code_snapshot`. יש לבדוק מצב DB חלקי לפני ניסיון החלה חוזר; בדיקת HTTP/DB חיה טרם הושלמה.

## כללי קטלוג

- מוצר פשוט הוא מוצר ללא וריאציות: מחיר ומלאי ברמת המוצר, קנייה ללא בחירת אפשרות.
- מוצר עם וריאציות מציג בחירה, וכל וריאציה נושאת מחיר, מלאי ותמונה משלה. תמונת המוצר נשארת נדרשת גם למוצר מורכב.
- מוצר חדש נשמר כטיוטת ביניים כדי להעלות תמונה בבטחה; אחרי שיש תמונת מוצר, מחיר ומלאי וקטגוריה פעילה הוא מתפרסם אוטומטית כפעיל. מוצר עם וריאציות יפורסם אחרי שלכל וריאציה פעילה יש תמונה. לכן ברירת המחדל העסקית היא פעיל ברגע שהמוצר מוכן לפרסום.
- סדר מוצר ותמונה מציע קפיצות של 10; השדות נשארים פתוחים להזנת מספר ידנית.
- אין מינימום כמות ללקוח. `default_min_sets` מוסר במיגרציה 011; `store_settings.minimum_product_subtotal` הוא מינימום כספי לפי סכום המוצרים, ללא משלוח. `set_size` נשאר לתיאור מארזי וריאציות, ו־Snapshot ישן נשמר.

## תמונות וגלריה כללית

- תמונת מוצר ווריאציה נשמרת ב־`product_images`; שיוך מוצר/וריאציה קובע את היעד. התמונה הראשונה בכל שיוך הופכת לראשית, ותמונות נוספות נשמרות בגלריה. ה־API תומך בהחלפת ראשית, אך פקדי בחירת ראשית הוסרו ממסך תמונות המוצר לפי בקשת המשתמשת. באותה עסקת DB התמונה הראשית הקודמת הופכת לתמונת גלריה. התמונה הראשית החדשה משמשת גם בתצוגת החנות.
- גלריה כללית נפרדת ב־`event_gallery_images`, עם נתיב, סדר, מצב פרסום וסימון `is_featured` לתמונה הגדולה בראש דף הבית. העלאה לנתיב גלריה בוחרת אוטומטית את bucket הגלריה; תמונת מוצר עולה בנתיב המדיה של המוצר.
- העלאה מקבלת JPEG/PNG/WebP עד 5 MiB, לאחר בדיקת חתימת קובץ.
- מחיקה מסמנת את הרשומה, מסירה את אובייקט Storage, ואז מוחקת metadata ורושמת Audit. כשל Storage משאיר רשומה מסומנת כדי שניתן יהיה לנסות שוב. קובץ מוצר שמשויך ליותר מרשומה אחת לא יימחק.
- בגלריה יש אזור גדול לגרירה ושחרור או בחירת כמה קבצים, תצוגות ממוזערות והסרת תמונה בודדת מהבחירה לפני העלאה. התמונות מוצגות ללא חיתוך וללא שמות קבצים.
- סדר הגלריה ניתן לשינוי בגרירה, במספר מיקום או בכפתורי הקדמה/אחורה לנייד ולמקלדת; המספור מתחיל ב־1 ומשקף את סדר התצוגה. הסדר המלא נשמר בשרת דרך `PATCH /admin/event-gallery/order`.
- כל תמונת גלריה חדשה מוצגת באתר כברירת מחדל. תיבת הסימון מאפשרת להסתיר אותה זמנית ללא מחיקה. כוכב נפרד בוחר מתוך התמונות המוצגות תמונה אחת לתמונה הגדולה בראש דף הבית; בחירה חדשה מבטלת את הבחירה הקודמת. הסתרת התמונה הגדולה מסירה ממנה את הכוכב.

## מימוש וממשקים

- ברשימת המוצרים מוצג תג בולט "מוצג באתר" או "לא מוצג באתר". מעבר מעל התג מציג את כל הסיבות המחושבות מהסטטוס, הקטגוריה, תמונת המוצר ותנאי הווריאציות; הנתונים מגיעים מ־API הניהול ומכוונים לכללי הסינון של קטלוג החנות.
- לאחר שמירת מוצר, וריאציה, תמונה, החלפת ראשית או מחיקת תמונה, רשימת הניהול נטענת מחדש כדי לעדכן סטטוס הצגה. API הניהול מחזיר סוג תמונה וקישור צפייה זמני חתום; הוא מציג את התמונות במסך העריכה ואת התמונה הראשית הממוזערת מימין לכל מוצר ברשימה. סדר ההצגה מוצג כמספר ללא סימן מטבע.

- ניהול מוצרים וקטגוריות: `/catalog`; גלריה כללית: `/gallery`.
- Public catalog: `GET /catalog`, `GET /catalog/:productId`, `GET /categories`; הגלריה הכללית: `GET /event-gallery`.
- פעולות Admin דורשות `operations_manager`. תמונות ומוצרים נרשמים ב־Audit; תגובות פרטיות משתמשות ב־no-store.
- Cart, Availability, Quote ויצירת הזמנה מקבלים `productId` ו־`productVariantId` אופציונלי. המלאי והמחיר נבדקים בשרת; Snapshot הזמנה למוצר פשוט שומר `product_variant_id` ריק.

## אימות וגבולות

- אומתו עד 14.10: API TypeScript, Admin typecheck, Storefront typecheck; בדיקות יחידה של קטלוג/Quote/הזמנה פשוטה עוברות. ב־18.10 עברו בניית API ו־Admin, שמונה בדיקות ניהול קיימות ושלוש בדיקות חדשות לשיוך ראשית/גלריה ולהחלפת ראשית. `scripts/check-docs.ps1` עבר. בדיקת DB אינטגרציה לא הופעלה; דפדפן הכלי לא הצליח להגיע לשרת הניהול המקומי, וגם בדיקת HTTP מקומית נחסמה על ידי הרשאות socket, ולכן התצוגה החיה טרם אומתה.
- Admin bundle build דורש להפעיל Vite עם `envDir: false` כדי שלא ינסה לקרוא `.env`; ההגדרה נוספה ב־`vite.config.ts`.
- לא בוצעו כתיבה ל־Production, בדיקת Supabase Storage, או החלת 011. בדיקות UI בדפדפן ותרחישי כשל Storage דורשים סביבת פיתוח עם DB ו־Storage זמינים.
- ב־18.10 התקבלה בהעלאת גלריה שגיאת `Failed to fetch`. בבדיקה נמצא שה־API המקומי לא היה פעיל; כשהופעל ללא תצורת DB/Supabase הוא עלה במצב מצומצם ללא נתיבי Admin ומדיה. הלקוח מציג כעת הודעת חיבור מפורשת במקום הטקסט הטכני, אך העלאה חיה דורשת API פעיל עם תצורת השרת המלאה.
- ב־18.10 תוקן טיפול הלקוח בתשובות הצלחה ריקות `204/205`, המשמשות מחיקה, שינוי סדר והפעלה/כיבוי. פעולות אלה אינן מנסות עוד לפרש גוף JSON שאינו קיים.

# Storage — מדיה

## Buckets

| Bucket | שימוש | ציבורי ישירות | סוגים | גודל מרבי |
|---|---|---:|---|---:|
| `zis-product-media` | תמונות מוצר/וריאציה | לא | JPEG, PNG, WebP | 5 MiB |
| `zis-event-gallery` | תמונות גלריית אירועים | לא | JPEG, PNG, WebP | 5 MiB |

ה־Buckets פרטיים בכוונה. השרת משתמש ב־service role רק בצד Backend ומחזיר Signed URL קצר־תוקף. אין לשים מפתח שירות בדפדפן. RLS של `storage.objects` מאפשר קריאה/כתיבה/החלפה/מחיקה רק ל־Admin פעיל; לקוח ציבורי מקבל מדיה דרך חוזי ה־API בלבד.

## זרימת העלאה

1. Admin מבקש העלאה עם Bucket, שם קובץ, MIME וגודל.
2. השרת בודק תפקיד, סוג, גודל ותוכן שהתקבל; שם הקובץ המקורי אינו הופך לנתיב אמין.
3. הקובץ נכתב לנתיב UUID חדש. כשל משאיר לכל היותר קובץ יתום שניתן לנקות לפי Audit.
4. לאחר הצלחה נשמר metadata ב־`product_images` או `event_gallery_images`, כולל `storage_path`, קשר, `alt_text`, סוג וסדר.
5. בהחלפה, החדש נבדק ונרשם תחילה. רק אחר כך ניתן לארכב את הרשומה והקובץ הישן; אין למחוק את הפעיל לפני הצלחה.
6. הציבור מקבל URL חתום לפי הצורך. URL שפג תוקפו נוצר מחדש, בלי שינוי metadata.

## הרשאות ותיעוד

- אין מדיניות `insert/update/delete` ל־`anon`.
- תמונת מוצר ציבורית דורשת מוצר פעיל, וריאציה תואמת אם קיימת, `is_deleted=false` ותמונה שנבחרה לפרסום.
- גלריית אירועים נפרדת מתמונות מוצר; רק `is_published=true` ו־`is_deleted=false` נשלפות.
- העלאה, החלפה, שינוי סדר, פרסום וארכוב נרשמים ב־`admin_audit_log` דרך השירות המאומת.
- SQL ההקמה נמצא ב־`zis-db/migrations/007_p1_storage_and_confirmation.sql`; חיבור Production נבדק דרך Login, אך הרשאות Storage דורשות ראיית בדיקה ייעודית בקריאה/פעולה מבוקרת.

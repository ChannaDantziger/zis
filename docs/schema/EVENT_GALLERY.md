# גלריית אירועים — סכמה וניהול

[אינדקס](../../PLAN_INDEX.md) · [דרישות תצוגה](../planning/STORE_CONTENT_AND_GALLERY.md) · [מיגרציה 005](../../zis-db/migrations/005_event_gallery_images.sql).
מפרט וטיוטת SQL מ־24.09.2026; לא אומת מסד חי.

`event_gallery_images` נפרדת מ־`product_images`: גלריית הבית כוללת אירועים בלבד, ותמונות מוצר נשארות משויכות למוצר/וריאציה. כך שינוי תמונת אירוע לא משנה קטלוג או הזמנות.

| שדה | תפקיד |
|---|---|
| `event_gallery_image_id` | מזהה יציב לתמונה |
| `storage_path` | נתיב קובץ ב־Storage; אינו קובץ בתוך DB |
| `alt_text` | תיאור נגישות חובה |
| `caption` | כיתוב אופציונלי לתמונה מוגדלת |
| `sort_order` | סדר בגלריה, עם מזהה כשובר שוויון |
| `is_published` | רק תמונות שאושרו לתצוגה ציבורית |
| `is_deleted` | ארכוב לוגי, בלי לשבור היסטוריה |
| `created_at`, `updated_at` | תיעוד מועדים |

מנהל מעלה קובץ ל־Storage דרך API מאומת, ממלא תיאור, קובע סדר ומפרסם במפורש. השרת מאמת סוג/גודל/קשר בין קובץ לרשומה, ומטפל בקובץ יתום אחרי כשל. החלפת קובץ לא מוחקת קובץ פעיל לפני שהחדש נבדק. נדרשים Audit של העלאה, שינוי סדר ופרסום.

RLS במיגרציה מאפשרת SELECT ציבורי רק ל־`is_published=true` ו־`is_deleted=false`. אין פוליסת כתיבה ציבורית. פעולות מנהל יבוצעו בשרת לאחר אימות Admin; הרשאות bucket, URL מדיה ותוקף cache יוגדרו וייבדקו יחד עם API. אין להסיק שפוליסת הטבלה לבדה מגינה על קובצי Storage.

בדיקת קבלה: מנהל מעלה שש תמונות, קובע סדר ומפרסם חמש. הציבור רואה בדיוק את החמש לפי הסדר; לאחר פרסום השישית או הסתרת אחת הרשימה מתעדכנת. תמונה מוסתרת אינה נשלפת ב־API, וקובץ שבור אינו מוצג כריבוע ריק.

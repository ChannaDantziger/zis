# גלריית אירועים — סכמה וניהול

[אינדקס](../PLAN_INDEX.md) · [דרישות תצוגה](../planning/STORE_CONTENT_AND_GALLERY.md) · [מיגרציה 005](../../zis-db/migrations/005_event_gallery_images.sql) · [מיגרציה 013](../../zis-db/migrations/013_event_gallery_featured_image.sql).
מימוש API/Admin מקומי עודכן ב־18.10.2026; מיגרציה 011 מסירה caption ו־alt_text, ומיגרציה 013 מפרידה בין פרסום לבין התמונה הגדולה. בעלת האתר דיווחה ב־19.10.2026 שמיגרציה 013 הורצה; מסד חי לא אומת ישירות.

`event_gallery_images` נפרדת מ־`product_images`: גלריית הבית כוללת אירועים בלבד, ותמונות מוצר נשארות משויכות למוצר/וריאציה. כך שינוי תמונת אירוע לא משנה קטלוג או הזמנות.

| שדה | תפקיד |
|---|---|
| `event_gallery_image_id` | מזהה יציב לתמונה |
| `storage_path` | נתיב קובץ ב־Storage; אינו קובץ בתוך DB |
| `sort_order` | סדר בגלריה, עם מזהה כשובר שוויון |
| `is_published` | רק תמונות שאושרו לתצוגה ציבורית |
| `is_featured` | תמונה ציבורית יחידה שמוצגת כתמונה הגדולה בראש דף הבית |
| `is_deleted` | ארכוב לוגי, בלי לשבור היסטוריה |
| `created_at`, `updated_at` | תיעוד מועדים |

מנהל מעלה קובץ ל־Storage דרך route ייעודי; הרשומה מתפרסמת כברירת מחדל. אפשר להסתיר אותה זמנית ולבחור בכוכב תמונה ציבורית אחת לתמונה הגדולה. אינדקס ייחודי ואילוץ DB מונעים יותר מתמונה גדולה אחת או בחירה בתמונה מוסתרת. נתיב ההעלאה קובע אוטומטית את bucket. השרת מאמת סוג, גודל וחתימת קובץ.

RLS במיגרציה מאפשרת SELECT ציבורי רק ל־`is_published=true` ו־`is_deleted=false`. אין פוליסת כתיבה ציבורית. פעולות מנהל יבוצעו בשרת לאחר אימות Admin; הרשאות bucket, URL מדיה ותוקף cache יוגדרו וייבדקו יחד עם API. אין להסיק שפוליסת הטבלה לבדה מגינה על קובצי Storage.

בדיקת קבלה: מנהל מעלה שש תמונות ורואה שכולן מוצגות כברירת מחדל. הוא מסתיר אחת ובוחר כוכב לאחרת; הציבור רואה חמש לפי הסדר והתמונה המסומנת מופיעה בראש הדף. בחירת כוכב חדש מחליפה את הקודם, ותמונה מוסתרת אינה נשלפת ב־API.

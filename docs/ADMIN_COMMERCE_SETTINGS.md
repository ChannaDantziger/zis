## כשל רשומת הגדרות חסרה — 09.10.2026

כאשר חסרה store_settings עם מזהה 1, קריאה ועדכון מחזירים 503 עם STORE_SETTINGS_NOT_CONFIGURED והודעה בעברית. אין יצירה אוטומטית בזמן קריאה. הבדיקות מכסות הגדרה חסרה, שחרור client, רשימות משלוח ריקות, ערכי JSON מפוענחים וקוד אבחון שאינו חושף פרטי חיבור.

בעלת האתר אישרה שהרשומה חסרה באמצעות EXISTS בקריאה בלבד. [תיקון הנתונים הממוקד](../zis-db/migrations/009_initialize_store_settings.sql) מוסיף אותה עם חנות סגורה, בלי לדרוס קיימת; ב־09.10.2026 בעלת האתר דיווחה שהריצה את 009 במסד. הסוכן אימת ברענון הדפדפן שהמסך נטען והחנות מוצגת כסגורה; לא בוצעו שמירה או אימות SQL ישיר. אין להריץ מחדש את Seed 002 כולו.

ב־14.10.2026 תוקנה שגיאת `/store-status`: PostgreSQL driver מפענח `jsonb` אוטומטית, והפענוח הכפול של ערך הזמן `09:00` נכשל. התיקון המקומי מסיר פענוח נוסף הן מקריאת המסחר והן מקריאת הגדרות Admin. אין מיגרציה נדרשת; חיבור ה־runtime אחרי התיקון טרם אומת.

## מה מנהלים בדשבורד

המסך `הגדרות משלוח וחנות` ב־`apps/admin-mobile` מאפשר למנהל פעיל:

- לפתוח/לסגור את החנות, לשנות הודעת נעילה, מינימום סכום מוצרים להזמנה (ללא דמי משלוח), כמה ימים קדימה מותר להזמין, אזור זמן וימי חלוקה.
- לשנות שעת יציאה כללית, cutoff להזמנה באותו יום וסטטוס ההכנה לאחר תשלום.
- להוסיף ולעדכן אזורי משלוח, עיר, שכונה, פעילות ושעת יציאה אזורית אופציונלית.
- לעדכן את שם ופעילות שיטות המשלוח, וליצור ולעדכן כללי מחיר לפי אזור, שיטה וטווח Sets.
- ליצור, להפעיל, להשבית ולעדכן סגירות מתוזמנות.

המחירים אינם נמצאים ב־Frontend ואינם מוזרקים כ־defaults בקוד. עדכון במסך נשלח ל־Backend ונשמר ב־PostgreSQL.

## API אדמיני

| שיטה | נתיב | פעולה |
|---|---|---|
| GET | `/admin/commerce/settings` | כל הגדרות העסק, אזורים, שיטות, כללים וסגירות |
| PATCH | `/admin/commerce/settings` | עדכון הגדרות עסק ו־system defaults |
| POST/PATCH | `/admin/shipping/zones[/:shippingZoneId]` | אזורים ושעות יציאה |
| PATCH | `/admin/shipping/methods/:shippingMethodId` | שם ופעילות שיטת משלוח |
| POST/PATCH | `/admin/shipping/rules[/:shippingRuleId]` | מחיר בסיס וטווח מארזים; תוספת גודל חוזרת לכל X מארזים מתוכננת. תוספות זמן ודחיפות מושבתות כרגע |
| POST/PATCH | `/admin/store-closures[/:storeClosureId]` | סגירות מתוזמנות |

הנתיבים הישנים תחת `/admin/commerce-settings` נשמרו כ־aliases לתאימות עם אב־הטיפוס הקודם. קריאה דורשת Admin פעיל; כתיבה דורשת תפקיד `operations_manager`.

## מקור אמת במסד

| נתון | מקור |
|---|---|
| פתיחת חנות, נעילה, הודעה ומינימום הזמנה | `store_settings` |
| cutoff, ימים, אזור זמן ושעת יציאה | `system_defaults` |
| עיר/שכונה/פעילות | `shipping_zones` |
| שם וקוד שיטת משלוח | `shipping_methods` |
| מחיר בסיס ותוספות | `shipping_rules` |
| חופשות וסגירות זמניות | `store_closures` |
| מי שינה ומה השתנה | `admin_audit_log` עם before/after |

`max_advance_days` נכתב גם ב־`store_settings.max_advance_days` וגם ב־`system_defaults` כדי לשמור תאימות למבנה הקיים; הקריאה מעדיפה את `system_defaults`.

## כללי שמירה ואכיפה

- סכומים אינם שליליים ומוגבלים לשתי ספרות עשרוניות.
- שעות נשמרות כ־`HH:mm`; תאריך סגירה חייב להיות ISO ולסיים אחרי תחילתו.
- כלל מחיר ללא התאמה גורם ל־Quote להיכשל ב־`BUSINESS_RULE_VIOLATION`; אין הנחת משלוח חינם implicit.
- מנוע ה־Quote קורא את המינימום, אזור פעיל, כללי המחיר, cutoff, ימי עבודה וסגירות מהמסד; מינימום ההזמנה נאכף לפי סכום המוצרים לפני הוספת המשלוח. לוח חגים אינו מופעל בשלב זה.
- פעולת כתיבה מתבצעת בטרנזקציה ונרשמת ב־Audit. RLS של טבלאות ההגדרות מגדיר הגנת DB ללקוחות Supabase; ה־API בודק בעצמו משתמש פעיל ותפקיד `operations_manager` לפני כתיבה, במיוחד כאשר Pool השרת משתמש בהרשאת DB חזקה.

## פריסת הסכמה

המיגרציה `zis-db/migrations/008_admin_commerce_settings.sql` מוסיפה את מפתחות ברירת המחדל, אינדקס אזורים, `shipping_zones.dispatch_time`, מדיניות Admin והערות הסכמה. היא forward-only ודורשת בדיקת ledger לפני הרצה. מפתחות חגים שנמצאים בסכמה נשמרים כהכנה עתידית ואינם משמשים כרגע לחסימת Quote.

לא נטענו מחירי משלוח עסקיים אוטומטית: המחירים יוזנו דרך המסך לאחר שה־DB זמין ולאחר קבלת הערכים העסקיים.

## מה עדיין נדרש לפני הפעלה

1. להריץ ב־Production בדיקת schema בקריאה בלבד דרך `DATABASE_URL`; אין ledger אמין להרצות הידניות ואין להדביק secrets למסמכים או לצ'אט.
2. אין להריץ את `apply:manual-migrations` ב־Production; שינוי schema מתבצע רק בתהליך השינוי המאושר של ספק ה־DB.
3. להזין דרך המסך את ערכי העסק: מחיר לכל אזור/טווח, cutoff, שעת יציאה, מינימום הזמנה, ימי חלוקה וסגירות.
4. לבצע Quote ויצירת הזמנה בסביבת בדיקה, כולל אזור ללא כלל, חנות סגורה, cutoff ומינימום הזמנה.

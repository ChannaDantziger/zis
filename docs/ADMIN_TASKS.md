# משימות ידניות בניהול

[אינדקס](PLAN_INDEX.md) · [אימות Admin](ADMIN_VERIFICATION.md) · [חוזי API](API_CONTRACTS.md).

תאריך אימות מקומי: 08.10.2026. המימוש קיים בקוד ונבדק ללא DB; לא אומת מול Production או במסך לאחר התחברות.

## שימוש במסך

- מסך `/tasks` נוסף לניווט המוגן. ניתן להציג משימות פתוחות, שבוצעו ושבוטלו, עם עימוד ורענון.
- יצירת משימה זמינה במסך המשימות ובדשבורד: כותרת בלבד, לאחר הסרת רווחים בקצוות, באורך 1–200 תווים.
- משימה ידנית נוצרת בעדיפות רגילה ובמצב פתוח. ניתן לסמן שבוצעה או לבטל אותה; פתיחה מחדש אינה ממומשת.
- משימות מערכת מוצגות עם מקור ועדיפות, וקישור להזמנה כאשר קיים. סגירתן דרך הפעולה הידנית חסומה; השלמת תהליכי המערכת נשארת להמשך.
- מונה המשימות הפתוחות בדשבורד נשלף בנפרד מרשימת התצוגה המוגבלת ל־20, ולכן אינו נחתך לפי אורך הרשימה.
- לאחר שינוי מתרעננים נתוני המשימות, הדשבורד, ההזמנות, פרטי ההזמנה והייצור. שינוי מסנן מחזיר לעמוד הראשון; סגירת הפריט האחרון מתקנת עמוד שאינו קיים עוד.

## חוזי שרת והגנות

| נתיב | בקשה | תגובה |
|---|---|---|
| `GET /admin/tasks` | `status=open/done/dismissed`, `page`, `pageSize` | `{ data, page: { page, pageSize, totalItems, totalPages } }` |
| `POST /admin/tasks` | `{ title }` בלבד | 201 עם המשימה שנוצרה |
| `PATCH /admin/tasks/:taskId` | `{ status: done/dismissed, version }` בלבד | המשימה המעודכנת |

כל הנתיבים דורשים מנהל תפעול פעיל עם תפקיד `operations_manager`; משלוחן וזהות ללא תפקיד מפורש נדחים. התגובות המוצלחות כוללות `Cache-Control: no-store`. עימוד ברירת מחדל 24, עד 50 פריטים לעמוד. מיון לפי עדיפות, זמן יצירה ומזהה; ספירה ושליפה משתמשות באותה טרנזקציית קריאה.

זהות היוצר והסוגר נלקחת מהאימות בשרת. שדות מקור, עדיפות או זהות בגוף הבקשה נדחים. הפעולות נשמרות עם `admin_audit_log` באותה טרנזקציה: כשל Audit גורם ל־rollback.

סגירה נועלת את המשימה ובודקת `version` המבוסס על `updated_at` לפני שינוי. ניסיון חוזר לסגירה לאותו מצב מחזיר את המשימה ללא כתיבה או Audit נוסף; בקשה למצב סגירה אחר נדחית. יצירה אינה משתמשת במפתח Idempotency: בכשל תקשורת יש לרענן ולבדוק את הרשימה לפני ניסיון נוסף.

| HTTP | קוד | משמעות |
|---:|---|---|
| 400 | `VALIDATION_ERROR` | כותרת, עימוד, UUID, גרסה או שדות לא תקינים |
| 404 | `TASK_NOT_FOUND` | המשימה אינה קיימת |
| 409 | `TASK_CHANGED` | גרסה השתנתה; יש לרענן |
| 409 | `TASK_ALREADY_RESOLVED` | כבר נסגרה למצב אחר |
| 409 | `SYSTEM_TASK_REQUIRES_WORKFLOW` | נדרש תהליך המערכת המקושר |

## ראיות וגבולות

- API: `npm.cmd run build` עבר. כלל הבדיקות המקומרות: 51 עברו, 0 נכשלו, בדיקת DB אחת דולגה עם `RUN_DB_INTEGRATION=false`.
- הבדיקות החדשות מכסות הרשאות HTTP, כותרת ושדות, עימוד, גרסה, נעילה, Audit טרנזקציוני, rollback, ניסיון סגירה חוזר, חסימת משימות מערכת וספירה שאינה מוגבלת לעמוד.
- Admin: typecheck ובניית Vite מקומית עברו באמצעות `configLoader: 'native', envDir: false`. קיימת התרעת bundle מעל 500 kB; זו אינה בנייה לפריסת Production.
- לא נוספה מיגרציה ולא הופעל שרת API מול DB. המימוש משתמש בטבלת `admin_tasks` הקיימת; התאמת הסכמה בפועל עדיין דורשת אימות בסוף הבנייה.
- UI לאחר Login, יצירה וסגירה מול DB, יצירת משימות מערכת אוטומטית, Push וספירת לא־נקרא אישית נשארים פתוחים. אין בכך השלמת P7/O23.

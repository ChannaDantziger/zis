# Docker, פריסה ותיעוד מסירה

[אינדקס](../PLAN_INDEX.md) · [P8/P9 בתוכנית](../IMPLEMENTATION_PLAN.md) · [מעורבות שלך](../OWNER_ACTIONS.md).
מצב: מתוכנן. אין כרגע Dockerfile/Compose/CI במאגר; מסמך זה אינו מדריך הרצה של תשתית קיימת.

## הכנה טכנית — אחריות הפיתוח

| תחום | תוצר נדרש | בדיקת קבלה |
|---|---|---|
| גרסאות | Node נתמך, lockfile, Git ו־build חוזר | התקנה ובנייה נקיות |
| Docker API | build רב־שלבי, runtime מצומצם, משתמש ללא root, כיבוי מסודר | container עולה ונכבה, health/readiness נכונים |
| הקשר build | dockerignore שמחריג קבצי סביבה, node_modules, מקורות רגישים | image/context אינם מכילים סודות |
| Frontend | build ציבורי ו־Admin נפרדים; הגדרות API פומביות בלבד | מסלולים ישירים ו־refresh עובדים |
| Compose | פיתוח מקומי עם health checks, ports ונתוני בדיקה | ריצה ממחשב נקי בלי תלות בייצור |
| DB פיתוח | Supabase תואם ל־auth.users ול־RLS או fixture מתאים | ארבע המיגרציות וה־Auth נבדקים; Postgres ריק לבדו אינו מספיק |
| סודות | הזרקה בזמן ריצה ממנהל הסודות של האירוח | אין סודות בקוד, image, build args או logs |
| CI | typecheck, lint, tests, build ובדיקת תיעוד | build נכשל על כשל אמיתי |
| פריסה | image tag/גרסה מזוהים ו־registry אם נבחר | פריסה חוזרת לאותה גרסה |
| תלויות | readiness למסד/שירותים קריטיים | DB מנותק אינו מדווח ready |

בחירת ספק אירוח ועלויות תיעשה עם בעלת האתר בעת ההקמה; אין כאן התחייבות לספק או למחיר. Docker Hub אינו חובה אם משתמשים ב־registry אחר או build אצל הספק.

## סביבות ופריסה

1. Development — נתוני בדיקה בלבד, מיגרציות ו־Integration.
2. Staging — מסלול קנייה מלא, סליקת Sandbox, דומיינים והרשאות דומים לייצור.
3. Production — רק לאחר סגירת חסמי השקה ואישור בעלת האתר על תוצר שנבדק.

תהליך מיגרציה חייב לדעת מה כבר הופעל. אין לערוך מיגרציה חיה ואין להפעיל rename מחדש על עיוור. גיבוי לפני שינוי ובדיקת התאמה לאחור/החזרת גרסה יתועדו. מסד ותמונות אינם נשמרים בדיסק הזמני של container.

לפני העלאה: DNS, HTTPS, CORS, כתובות חזרה ו־Webhook, קישורי מדיה, timeouts, rate limits ופרטי קשר לטיפול בכשל. מאמתים שגם Build של החנות אינו מכיל קוד Admin.

## אמינות ושחזור

- להגדיר עם בעלת האתר מהו אובדן מידע נסבל ומהו זמן התאוששות רצוי; לא להמציא יעדים עסקיים.
- גיבוי DB ומדיה והליך שחזור; לתרגל שחזור להזמנה, תמונות והגדרות בסביבה מבודדת.
- לרשום ניסיון ספק, מזהה אירוע, מצב ותוצאת פעולה כדי שאפשר יהיה להתאושש מקריסה.
- להגדיר ניטור לכשל API/DB, תשלום ללא הזמנה עקבית, מסמך שלא הופק והתראות שלא נמסרו.
- להגדיר בעל תפקיד מקבל התראה ומה עושים אחרי שלושה ניסיונות כושלים.
- בדיקת רכישה אחרי פריסה וחזרת גרסה שנוסתה; החזרת אפליקציה אינה מחזירה אוטומטית מיגרציה.

## דוקומנטציה בסוף — מה יימסר

לפי הבקשה, תיעוד המערכת הסופי נכתב אחרי שהקוד והתהליכים נבדקו. במהלך העבודה נשמרים רק החלטות, חוזים נחוצים, התקדמות ופערים, כדי שלא לאבד הקשר.

| מסמך מסירה מתוכנן | מה חייב להכיל | מתי כותבים/מאמתים |
|---|---|---|
| התקנה והרצה | תלויות, פקודות, שמות הגדרות ללא ערכים סודיים | אחרי build נקי ב־P8 |
| API | נתיבים אמיתיים, קלט/פלט, הרשאות ושגיאות | בסוף כל יכולת; איחוד ב־P9 |
| DB ו־Storage | מיגרציות שהופעלו, קשרים, RLS, העלאה וארכוב | אחרי אימות P1/P8 |
| מדריך חנות/Admin | מוצרים, תמונות, מלאי, תאריכים, הכנה, אריזה, ביטול | אחרי בדיקת U13 |
| תשלום ומסמכים | הצלחה/כשל, התאמה לספק, retry וביטול כספי | אחרי Sandbox |
| תפעול ותקלות | health, logs מסוננים, ניטור, escalation וצעדי תיקון | אחרי תרגילי כשל |
| פריסה ושחזור | Docker, registry, deploy, backup/restore/rollback | אחרי הרצה בפועל |
| מסירת QA | תרחישי קבלה, תוצאות, מגבלות ופערים שנדחו | לפני אישור השקה |

אלה תוצרים עתידיים, ולכן אינם מקושרים לקבצים שלא קיימים. עם יצירתם מוסיפים קישורים ל־[DOCS_INDEX](../DOCS_INDEX.md) ולאינדקס הראשי.

## שער מסירה

- אין חסם קריטי פתוח; לדחייה יש בעלים והשלכה ידועה.
- TypeScript, Lint, בדיקות רלוונטיות ו־E2E עברו; הרצה שנחסמה אינה pass.
- מדריך ההתקנה נוסה בסביבה נקייה ומדריך התפעול נוסה עם בעלת האתר.
- כל מסמך עד 320 שורות; אין קישור שבור או מסמך MD שאינו באינדקס.
- מקבלים אישור השקה על תוצר בדוק, ואז מבצעים פריסה ובדיקות לאחר העלייה.

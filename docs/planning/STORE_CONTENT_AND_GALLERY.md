# תוכן החנות, תמונות וגלריית אירועים

[אינדקס](../../PLAN_INDEX.md) · [דרישות חנות](STOREFRONT_REQUIREMENTS.md) · [תוכנית](../../IMPLEMENTATION_PLAN.md) · [סכמת גלריה](../schema/EVENT_GALLERY.md).
החלטות בעלת האתר מ־24.09.2026. זהו חוזה יעד ל־P1–P4/P7. [תצוגת הבדיקה](../../prototypes/zis-review/README.md) משתמשת בתמונות ונתוני המחשה מתוך `Lis-standalone.html`; עדיין אין חיבור מוכח ל־DB או ל־Storage חי.

## מקור תצוגה ותוכן

- `Lis-standalone.html` הוא המקור החזותי היחיד. התצוגה לא נבנית מהקובץ האחר.
- יש אזור מוצרים אחד ושמו **קטלוג**. סינון לפי קטגוריות הוא חלק מאותו אזור; אין מקטע קטלוג נוסף.
- כל מוצר, קטגוריה, וריאציה, מחיר למארז, גודל מארז, מינימום וזמינות נשלפים מן ה־DB דרך API ציבורי. רכיב אינו מכיל רשימת מוצרים, מחירים או ערים כתובים בקוד.
- מחירים סופיים וחישוב משלוח נקבעים בשרת בזמן הזמנה. ערים ושכונות פעילות נשלפות מה־DB; טופס קופה אינו מציע עיר שלא פורסמה.
- בתצוגת האתר אין כתובת עסק. בקופה נשאר שדה כתובת יעד למשלוח, לפי הבהרת בעלת האתר.
- פרטי קשר, כשרות, הבטחות זמני תגובה ומחירים שאינם מאושרים לא מועתקים מנתוני ההמחשה למערכת החיה.

## זרימת נתונים מתוכננת

| מה מוצג | מקור האמת | איך מגיע למסך |
|---|---|---|
| קטגוריות ומוצרים | `categories`, `products` | API מסנן רק רשומות פעילות ומפורסמות; חיפוש, מיון ועימוד בשרת |
| וריאציות, Sets, מחיר וזמינות | `product_variants` ושדות מוצר | API מצרף רק וריאציות פעילות; קופה מאמתת שוב מחיר/מלאי |
| תמונות מוצר | `product_images.storage_path` ו־Storage | API מחזיר URL תקף, סדר, alt וקשר מוצר/וריאציה |
| ערי משלוח | `shipping_zones` | API מחזיר ערים פעילות בלבד, בלי מערך קבוע ברכיב |
| מחיר משלוח | `shipping_rules` וכללי החנות | quote בשרת לפי כתובת/כמות/תאריך; אין מספר משלוח קבוע בדפדפן |
| גלריית אירועים | `event_gallery_images` ו־Storage | API מחזיר רק תמונות מפורסמות לפי `sort_order` ומזהה יציב |

שכבת API client אחראית לטעינה, רענון, שגיאות ו־cache. רכיבי React/Mantine מציגים את הנתונים שהתקבלו; MobX שומר מצב בחירה/עגלה. אין להזין נתוני עסק בתוך JSX, CSS או קובץ קבוע שמגיע ל־Production. תמונות החנות והגלריה יכולות להיות באותו שירות Storage אך נשמרות בטבלאות נפרדות.

## תמונות ומראה

- אזור תמונה קבוע ביחס מוסכם. ברשימות ובגלריה: `object-fit: cover` עם חיתוך מבוקר, כך שכל המסגרת מלאה ללא שוליים ריקים ומתיחה. במבט מוגדל: `contain` כדי לראות את כל התמונה.
- כל תמונות גלריית האירועים באותו גודל. במסך מחשב ממוצע, כ־1280–1600 פיקסלים, מוצגות חמש במקביל; במסכים צרים מספר העמודות יורד בלי גלילה אופקית.
- לחיצה על תמונה פותחת אותה בגדול. חצים עוברים לקודמת/הבאה, ומתחת מופיעות תמונות ממוזערות לחיצה. Escape סוגר, המיקוד נשאר בחלון וחוזר לתמונה הפותחת בסגירה.
- בגלריית הבית מוצגות **תמונות אירועים בלבד**, לפי החלטת בעלת האתר. גלריית התמונות בדף מוצר היא תכונה נפרדת המבוססת על `product_images`.
- בדף הבית תמונות אירועים ניתנות לשינוי וסידור בניהול. שדות הקובץ/כיתוב/סדר/פרסום ב־DB; הקובץ עצמו ב־Storage. תמונה לא מפורסמת או שנמחקה לוגית אינה נחשפת בשליפה הציבורית.
- פינות **ימין למעלה ושמאל למטה מעוגלות**; שמאל למעלה וימין למטה חדות. להחיל על כרטיסים, תמונות, כפתורים וחלוניות באופן עקבי.
- במסך ממוצע קצות אזורי התוכן מיושרים לקו אחד, בערך אינץ׳ מכל קצה; בנייד השוליים קטנים באופן יחסי.
- תחתית כרטיסי מוצר וחבילה נשארת באותו קו גם כשאורך תיאור שונה. טקסט שמוגבל יוצג עם “עוד…”; לחיצה בכל הכרטיס, בעכבר או במקלדת, פותחת פרטים מלאים.

## מצבי קצה ובדיקת קבלה

1. מוצר/עיר/מחיר משתנים ב־DB ונשלפים מחדש למסך בלי עריכת רכיב.
2. תמונה מתחלפת בניהול: הנתיב/סדר ב־DB, הקובץ ב־Storage, והרכיב מציג את הגרסה החדשה. תמונה חסרה מקבלת מצב חלופי מוגדר ולא שטח שבור.
3. חמש תמונות אירועים בגודל אחיד על מחשב; קליק, דפדוף, בחירה ממוזערת, Escape, מקלדת ומובייל נבדקים.
4. כל תמונה ממלאת את מסגרת הרשימה/גלריה; במבט מוגדל רואים את כולה. אין מתיחה או שטח ריק בגלל הזזת parallax.
5. כרטיסים ארוכים וקצרים מסתיימים באותו קו; “עוד…” וקליק בכרטיס פותחים פרטים מלאים.
6. כתובת עסק אינה מוצגת בשום אזור ציבורי; כתובת המשלוח נשארת בטופס ההזמנה ונגישה רק לפי הרשאות מתאימות.
7. נתוני המחשה וקופה מדומה אינם חלק מה־Build החי. בהיעדר DB מוצג מצב ריק/שגיאה ברור, ולא מוצר מומצא.

## מקור נתונים וזרימת שליפה

1. מנהלת יוצרת מוצר/וריאציות ומעלה תמונות דרך API מאומת.
2. השרת מאמת בעלות על הקשר, נתונים ומדיה; שומר קבצים ב־Storage ומטא־דאטה ב־DB.
3. פעולה מפורשת מפרסמת את המוצר לאחר בדיקת שדות, וריאציה פעילה ומדיה.
4. API ציבורי מחזיר רק קטגוריות/מוצרים/וריאציות מותרים עם תמונה ראשית.
5. דף מוצר מקבל נתונים וגלריה מה־API; בחירת וריאציה מחליפה מחיר, קוד, זמינות ותמונות.
6. API client ו־Query מטפלים ב־cache/refetch/retry; רכיב התצוגה אינו מכיל fetch/SQL.
7. שינוי או הסתרה בניהול מבטלים cache מתאים ומשתקפים בחנות.

### חוזי API שיש להשלים ב־P1

אלה יעדי חוזה, לא endpoints קיימים. Quote לחישוב אינו Reservation או הבטחת מחיר. מסך אישור אורח אינו מאפשר קריאת מידע אישי לפי orderNumber בלבד — O16.

## מחזור חיים של תמונה

- מזהה נכס יציב; storage_path נשמר במסד, לא Blob URL זמני מקובץ ה־HTML.
- להגדיר bucket והרשאות פרסום/טיוטה; מדיה פרטית אינה הופכת ציבורית רק מפני שקיים URL.
- להחליט מגבלת משקל/מידות וסוגים, בדיקת תוכן הקובץ, הקטנה והפקת גרסאות תצוגה.
- העלאה שנכשלה אינה משאירה תמונה ראשית שבורה; קובץ יתום מטופל בתהליך ניקוי מוגדר.
- תמונות וריאציה קודמות לתמונות מוצר משותפות; סדר אחיד לפי sort_order ומפתח נוסף לשוויון.
- לשמור alt, רוחב/גובה אם נחוץ, ראשית וסדר; ללא שכפול תמונה ראשית פעילה.
- להציג placeholder חסר/כשל, ללא לולאת onError; loading לתמונה אינו חוסם קנייה לנצח.
- לטעון תמונות קטנות לרשימה, lazy-loading מחוץ למסך ומידות קבועות למניעת קפיצות.
- בהחלפה/ארכוב יש להחליט על cache ועל קובץ ישן; להימנע ממחיקה שוברת קישורים.
- בדיקת קבלה: מנהלת מעלה שתי תמונות, משנה סדר/ראשית, בוחרת וריאציה ומסתירה מוצר; החנות משקפת כל שינוי.

## מסכי החנות ושיפור חוויית ה־HTML

- בית: מיתוג, קטגוריות ומוצרים נבחרים עם דרך ברורה לקנייה. תוכן אירועים לא יסתיר את החנות.
- קטלוג: סינון, מיון וחיפוש, ספירת תוצאות, “ללא תוצאות” ואפשרות ניקוי מסננים.
- כרטיס מוצר: שם, תמונה, מחיר ליחידה × גודל Set = מחיר Set, וכן מצב זמינות. המחיר ליחידה הוא מקור המחיר גם בווריאציה; סך השורה מחושב ממחיר Set × הכמות שנבחרה.
- מוצר: בחירה מפורשת של וריאציה, כמות Sets ומינימום, תיאור ומידע מוצר רלוונטי.
- גלריית אירועים: חמש תמונות אחידות בשורה במסך ממוצע, יחס מלא בלי מתיחה; Modal עם Escape, חצים, ממוזערות, focus trap וחזרה לכפתור הפותח. תמונות מוצר נפרדות.
- עגלה: מוצר/וריאציה, כמויות, עריכה/הסרה, הסבר מינימום וסכום משוער לפני משלוח.
- Checkout: פרטי קשר, עיר/שכונה/כתובת, תאריך, שעת יציאה קבועה, הקדשה והערות; הודעות שגיאה ליד שדות. אין בחירת חלון מסירה בשלב הראשון.
- הלוח מציג רק תאריכים שהשרת מאשר: עבר, תאריך מעבר לטווח שהוגדר בניהול, סגירה פעילה והיום אחרי cutoff אינם לחיצים. מתחתיו מופיע נוסח ה־cutoff מהשרת; גם `quote` ו־`orders` מאמתים שוב את הבחירה. לוח חגים אינו מופעל בשלב זה.
- סגירת חנות מציגה הודעה עם פתיחת האתר ומשביתה כל "הוסף לסל". אין להסתפק בחסימה חזותית: יצירת הזמנה נבדקת בשרת.
- אין להציג כתובת עסק באתר; שדה כתובת יעד למשלוח נשאר בקופה. ערים, מוצרים, מחירים ותמונות מגיעים מ־DB/Storage דרך API, בלי ערכי עסק משתנים בתוך רכיבים.
- שליחה: למנוע לחיצה כפולה, להראות pending וכשל ניתן לשחזור, לשמור עגלה בכשל.
- אישור: מזהה שרת ומצב תשלום מאומת; לא טענה שנשלח אימייל אם לא נשלח.
- FAQ: שאלות ותשובות פעילות נטענות מה־API ומה־DB; ניהולן כולל טיוטה, פרסום, סדר וארכוב.
- להסיר איסוף עצמי, תשלום מדומה, משלוח חינם ודחיפות ציבורית הסותרים החלטות קיימות.
- לבחור טקסטי עברית/אנגלית מאושרים, ברירות מחדל לשפה ו־dir; לא להציג מפתח תרגום חסר.

מיפוי יעד: Header/Footer/MobileTabBar → רכיבים משותפים; ProductsGrid → אזור קטלוג יחיד; Gallery בבית → event-gallery; גלריית מוצר → product-gallery; CartProvider → MobX cart store; CheckoutModal/MobileSteps → checkout; ConfirmationPane → order-confirmation; TweaksPanel → כלי פיתוח בלבד. [כללי התוכן והמראה המפורטים](STORE_CONTENT_AND_GALLERY.md).

## תפעול — שלא יישמט מהחנות

- רשימת הזמנות לפי יום אספקה/סטטוס, פרטים מלאים והבחנה בין pending ל־paid.
- רשימת הכנה לפי מוצר/וריאציה/כמות ותאריך; חוסר ודרישת השלמה גלויים.
- אריזה, בדיקת תכולה והקדשה, הדפסת פרטי משלוח, סימון יציאה ומסירה.
- ביטול מורשה בכל שלב; אחרי אריזה שאלת החזקה בחבילה, אישור נוסף ובחירת טיפול בתשלום. עצירת אספקה, בירור כשירות החזרה למלאי ושחרור הקצאות פעם אחת לפי [מטריצת החריגים](OPERATIONS_EXCEPTIONS.md).
- ניהול קטלוג ותמונות אינו מחייב עריכת SQL ידנית.
- הודעות והתראות מציגות מצב שליחה/כשל ואפשרות טיפול; Push אינו מושלם בכתיבת שורה בלבד.

## תרחישי קבלה חוצי מערכת

1. מוצר חדש עם תמונות מתפרסם → חיפוש מוצא אותו → וריאציה נכונה נרכשת.
2. מחיר משתנה כשהעגלה פתוחה → הלקוחה רואה שינוי → השרת שומר Snapshot עדכני.
3. תמונה/מוצר מוסתרים → אין דליפה דרך קטלוג, קישור ישיר או cache ישן מעבר למדיניות שנבחרה.
4. תשלום נכשל/מתעכב/מדווח פעמיים → אין חיוב או הפחתת מלאי כפולים.
5. שתי הזמנות מתחרות על אותה קיבולת → אין יתרה שלילית והכשל מטופל לפי O04.
6. מנהלת מכינה ואורזת → הקדשה וכתובת נכונות → סטטוס מסירה נשמר.
7. ביטול חוזר → אין החזר מלאי נוסף; תשלום ללא זמינות מקבל טיפול מוסכם.
8. ניתוק API, קטלוג ריק, תמונה שבורה, localStorage פגום ו־session שפג → הודעה שימושית וללא הצלחה מדומה.

אחרי כל שלב מעדכנים התקדמות. תיעוד סופי למשתמשת ולתפעול ייכתב לאחר אימות, לפי [תוכנית המסירה](DELIVERY_AND_DOCUMENTATION.md).

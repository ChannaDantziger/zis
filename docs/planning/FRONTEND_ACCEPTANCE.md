# בדיקות קבלה וגבולות שלב Frontend

[תוכנית Frontend](../FRONTEND_BUILD_PLAN.md) · [תוכנית כוללת](../IMPLEMENTATION_PLAN.md) · [אינדקס](../PLAN_INDEX.md).

> המפרט הבא מתייחס לאבן דרך של ממשק בלבד; סליקה, טיפול בכשל כספי ותפעול מחויבים לפני השקת חנות. סדר השלבים בתוכנית הכוללת גובר על סדר היסטורי כאן.

## 6. מה לא נכלל בשלב הראשון

- סליקה אמיתית.
- חשבונית ירוקה.
- WhatsApp, SMS או Email אוטומטי.
- Chat או סימולטור אירוע.
- הרכבת חבילות מתקדמת.
- חשבונות לקוח.
- הזמנות טלפוניות.
- Refund.
- תפקידי Admin מורכבים.

## 7. פערים והחלטות שצריך להשלים

לפני חיבור Production יש להשלים:

1. רשימת מוצרים, וריאציות ומחירים.
2. גודל Set לכל מוצר.
3. מינימום Sets לכל מוצר.
4. אזורי משלוח ומחירים.
5. ימי עבודה ושעת Cutoff.
6. ספק סליקה עתידי.
7. סוג המסמך החשבונאי.
8. מקור התמונות הסופי וה־Storage.
9. הרשאת Admin וחיבור Auth.
10. מדיניות פרטיות, שמירת נתונים ונגישות.

## 8. סדר עבודה מומלץ בפועל

```text
מקור HTML
   ↓
מפת מסכים ורכיבים
   ↓
React + Theme + RTL
   ↓
דף בית וקטלוג
   ↓
מוצר וגלריה
   ↓
MobX Cart
   ↓
Checkout ו־Validation
   ↓
חוזי API
   ↓
Database ו־Backend
   ↓
בדיקות ו־Browser QA
   ↓
Admin נפרד
```

## 9. Definition of Done לשלב Storefront ראשון

השלב ייחשב מוכן כאשר:

- האתר עולה בפקודת פיתוח אחת.
- דף הבית תואם לתצוגה המאושרת.
- קטלוג ומוצר פועלים עם נתוני API.
- גלריה נגישה עובדת במובייל וב־Desktop.
- עגלה נשמרת מקומית ומתעדכנת נכון.
- Checkout מונע שליחת נתונים לא תקינים.
- המחיר והמלאי מאומתים בשרת.
- שגיאות מוצגות למשתמש בעברית ובאופן נגיש.
- אין שגיאות TypeScript או Lint.
- בוצעה בדיקת דפדפן ידנית במסך מובייל ובמסך רחב.

## 10. החלטת התחלה

הצעד הראשון לביצוע הוא הקמת `Storefront` נקי והעברת דף הבית והקטלוג מה־HTML הארוז לרכיבי React קטנים. לאחר שהמראה מאושר, מחברים את העגלה, ורק לאחר מכן את ה־Checkout ואת ה־Backend.

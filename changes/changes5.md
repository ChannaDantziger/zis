# Changes 5 — בקשות והצעת צעדי טיפול

הבקשות נשמרות כלשונן, ומיד אחריהן מופיעה הצעת דרך הטיפול. זו הצעת תכנון; היא אינה אישור לשינוי DB או להרצת SQL.

## 1. מספור הזמנות בסדר רץ החל מ־1000

**הבקשה:** מה צריך לעשות בשביל להפוך את מספרי ההזמנות למספקים בסדר רץ בני החל מ 1000

**מה אעשה:** אבדוק איך מספרי הזמנות נוצרים ונשמרים, ואמפה הזמנות קיימות כדי שלא ליצור כפילויות.
**צעדים:** אגדיר את כלל המספור, אתייחס להזמנות ישנות וליצירה בו־זמנית, ואז אתעד ואממש פתרון עם בדיקות מתאימות.
**מודל ומקביליות:** מודל חזק לעבודה על Backend ומסד הנתונים. אפשר במקביל להכין אפיון UI, אבל מימוש השרת והמספור מחייב תיאום. כל שינוי DB יוכן לבדיקה ולא יורץ אוטומטית.

**סטטוס 17.11.2026:** המימוש המקומי הותאם להקצאת מספר מתוך sequence של PostgreSQL; הוכנה מיגרציה 019 ששומרת מספרים קיימים וממקמת את הרצף אחרי המספר המספרי הגבוה ביותר, עם מינימום 1000. בעלת האתר דיווחה שהמיגרציה הורצה. מצב ה־DB והמספור בפועל טרם אומתו עצמאית.

## 2. הצגת הזמנות וייצור בדף המרכזי ובניווט המתאים

**הבקשה:** תוכל לשים את הקומפוננטות של הזמנות , יצור, גם בדף המרכזי וגם תחת הניווט המתאים?

**מה אעשה:** אבדוק אילו רכיבים ומסכים קיימים בדף הבית ובמסכי ההזמנות והייצור.
**צעדים:** אמפה את הנתיבים והניווט, אגדיר היכן כל רכיב מופיע, ואחבר אותם תוך שמירה על פעולות והרשאות קיימות.
**מודל ומקביליות:** מודל חזק ל־Frontend. אפשר לבדוק את מסך ההזמנות ואת מסך הייצור במקביל, בתנאי שמתאמים את שינויי הניווט והקבצים המשותפים.

## 3. תצוגה והדפסה של דוחות משלוח, ייצור ואריזה

**הבקשה:** צריך להוסיף אפשרות תצוגה והדפסה של הדוחות המתאימים, משלוח , יצור, אריזה בתוך הקומפוננטות המתאימות

**מה אעשה:** אבדוק אילו נתונים ודוחות כבר קיימים לכל אחד משלושת התחומים ומה חסר להצגה ולהדפסה.
**צעדים:** אגדיר את תוכן הדוחות, אבנה תצוגה מסוננת ופריסת הדפסה, ואוודא שההדפסה כוללת את הנתונים הנכונים בכל תחום.
**מודל ומקביליות:** מודל חזק ל־Frontend ולחיבור API. אפשר לעבוד על דוחות משלוח, ייצור ואריזה במקביל לאחר הסכמה על מבנה משותף; אם נדרש API חדש, יש לתאם את החוזה תחילה.

## 4. SQL ל־20 הזמנות להיום ממוצרים קיימים

**הבקשה:** תכין לי SQL ל20 הזמנות להיום עם מוצרים קיימים בDB

**מה אעשה:** אבדוק את הסכמה, קשרי הטבלאות ודרך יצירת ההזמנות, בלי להתחבר או לשנות DB בפועל.
**צעדים:** אכין סקריפט SQL לעשרים הזמנות עם מוצרים קיימים, אוסיף בדיקות מקדימות ומניעת כפילויות ככל שהסכמה מאפשרת, ואסביר כיצד לבדוק אותו לפני הרצה.
**מודל ומקביליות:** מודל חזק עם הבנת SQL/PostgreSQL. אפשר במקביל לבדוק את הסכמה ולנסח תרחישי בדיקה, אך הסקריפט צריך להתבסס על אותה גרסת סכימה. אכין אותו בלבד; ההרצה תישאר ידנית דרך תהליך ה־DB המאושר.

## 5. תוכן הבקשה חסר

**הבקשה:** במסמך המקורי מופיע רק המספר „5”, ללא פירוט.

**מה אעשה:** אשאיר את הסעיף מסומן כחסר ולא אנחש את כוונת הבקשה.
**צעדים:** נשלים את נוסח הדרישה, נוסיף אותה למסמך, ואז נעריך את דרך הטיפול והצעדים הנדרשים.
**מודל ומקביליות:** אין צורך לבחור מודל פיתוח עד שיש דרישה. אפשר להתקדם בבדיקת סעיפים 1–4 במקביל.
